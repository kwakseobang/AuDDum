# 투표 만들기·관리자 조치·로그인과 회원 기능 페이지

## 왜 하나

이슈 #109의 두 번째 PR이다. 규칙이 가장 많은 세 기능(투표 생성·삭제, 관리자 조치, 로그인과 회원)을 옮기면 UC 17개가 모두 기능 페이지로 간다. 그러면 다음 PR에서 `사용자-시나리오`를 폐지할 수 있다.

## 무엇을 건드리나

- 새로 만든다: `02-투표-만들기`, `06-관리자-조치`, `07-로그인과-회원`(각각 `.d2`, `.svg`), 이 sketch
- 옮긴다: UC-05·06·07·08·09·15·16·17, 정책 P-01·02·04·05·06·13·14·15·16·17·20·21·22·26·27·29·30, 운영 시나리오 OP-01~10
- 건드리지 않는다: R 정의(도메인 모델), API 명세, 코드

## 어떻게 할까

- 양식과 작성 원칙은 1단계 합의를 그대로 쓴다.
- 여러 기능에 걸친 정책의 주인을 정했다(PR 1에서 보류한 것):

| 정책 | 주인 | 이유 |
|---|---|---|
| P-01(숨김·삭제 상태) | 06 | 숨김·삭제·복구를 하는 쪽이 관리자 조치라서 |
| P-05, P-13(정지 규칙) | 07 | 회원 상태가 바뀔 때의 규칙이라서. 06은 링크만 한다 |
| P-29, P-30(조치 직전 요청, 권한) | 06 | 조치와 권한에 대한 정책이라서 |

- 회원 상태 전이도는 도메인 모델에 이미 있어서 `사용자-시나리오`의 Mermaid 상태도는 옮기지 않고 지웠다(중복). 07은 도메인 모델로 링크한다.
- OP 표는 정의라서 그대로 옮기되, OP-07 비고의 "2번 섹션"을 링크로 고쳤다(옮기면 가리키는 곳이 달라진다).
- `예외-정책`의 `확정된 정책`은 색인 표 하나로 바꿨다. 정책 28건이 모두 기능 페이지로 갔다.
- 투표 복구(`restore`)와 정지 해제(`unsuspend`)는 문서에는 있지만 코드에는 아직 없다(#20). 문서가 기준이므로 06에 "구현 전"이라고 적었고, 07의 정지 해제 규칙은 테스트 칸에 "구현 전(#20)"이라고 적었다.

## 어디에 넣나

| 내용 | 위치 |
|---|---|
| 기능 페이지 3개와 흐름도 | `docs/features/` |
| 옮긴 정의의 원래 자리 | `사용자-시나리오`, `예외-정책`에 이동 안내와 색인만 남김 |

## 어떤 순서로

1. 원문(UC·P·OP, API 명세, 도메인 규칙, 테스트 이름)을 읽고 페이지 초안
2. 원문 대조표로 사라진 문장을 찾아 되살림(이번에 3건 발견)
3. 원본 문서에서 옮긴 정의를 지움
4. `docs-check`, `test-docs-check`로 정의 개수(P=29, OP=10, UC=17, R=60)가 그대로인지 확인

## 지킬 규칙

정의는 한 번만(`docs-check`). 기능 페이지 이력과 sketch 머리말이 서로 링크. 코드 주석에 문서 이름을 쓰지 않는다.

## 막아야 할 것

- 옮기면서 문장을 잃는 것: 대조표로 찾아 아래 3건을 되살렸다.
- 아직 구현하지 않은 기능을 구현된 것처럼 적는 것: 복구·정지 해제에 "구현 전"을 표시했다.
- 규칙 표의 테스트 이름이 실제와 어긋나는 것: 클래스 존재를 `find`로 확인했다.
