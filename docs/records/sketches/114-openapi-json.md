# OpenAPI 문서를 코드에서 만들고 기능 페이지와 대조한다

## 왜 하나

프런트나 새 팀원이 서버를 띄우지 않고도 API를 볼 수 있어야 한다(운영에서는 스웨거를 끄고, 개발 서버가 없다). 손으로 쓴 `API-명세`는 코드와 어긋날 수 있다. 협업자가 있다고 보고(사용자 결정, 2026-10-30) 코드에서 OpenAPI 문서를 만들어 커밋하고, 어긋나면 빌드가 실패하게 한다. 이슈 #114의 세 번째 PR이다. 손으로 쓴 `API-명세`를 없애는 일은 다음 PR이다.

## 무엇을 건드리나

- 만든다: `docs/generated/openapi.json`(생성물), 이를 만들고 비교하는 테스트 `OpenApiDocTest`
- 만든다(검사): `docs-check`가 기능 페이지의 "사용하는 API"와 `openapi.json`을 서로 대조한다
- 고친다: `02-투표-만들기`의 "사용하는 API"(작성자 삭제 API는 구현 전), `generated/README`, `index`의 `docs-check` 설명
- `features`가 `02-투표-만들기`뿐인 이유: 이 PR의 중심은 생성 도구이지만, 대조 검사가 찾은 문서 오류(작성자 삭제 API가 아직 없다)를 `02`에서 고쳤고, 기능 페이지를 고치면 이력에 남기는 것이 약속이라서다
- 건드리지 않는다: 컨트롤러·스웨거 어노테이션, `API-명세`(다음 PR), 코드

## 어떻게 할까

| 질문 | 결정 | 이유 |
|---|---|---|
| 어떻게 만드나 | 통합 테스트가 `/v3/api-docs`를 호출해 받은 JSON을 키 순서를 고정해 들여쓰고, 서버 주소는 뺀다. 같으면 통과, 다르면 실패, `DOCS_UPDATE=1`이면 다시 쓴다 | 오류 코드 표와 같은 방식이라 도구가 늘지 않는다. 키를 고정해야 PR diff가 읽힌다 |
| 무엇을 대조하나 | 기능 페이지 표의 `METHOD 경로` 행이 `openapi.json`에 있는지, `openapi.json`의 모든 API가 어느 기능 페이지에 있는지 | 어느 기능에도 안 걸린 API는 기획자가 모르는 API다(#99 합의) |
| 필터가 처리하는 경로 | 카카오 로그인 경로 2개는 OpenAPI에 없어서 `docs-check`에 허용 목록으로 둔다 | 컨트롤러가 아니라 스프링 시큐리티가 처리한다 |
| 구현 전 API | 같은 줄에 "구현 전"이라고 적으면 넘어간다 | 정지 해제·투표 복구(#20)처럼 설계만 있는 것 |

## 조사 결과: 스웨거 어노테이션은 얼마나 충실한가

- 코드의 API는 14개이고 모두 `summary`, `description`, 상태별 `@ApiResponse`(오류 코드 이름 포함), DTO 필드의 `@Schema`(설명·예시)가 있다. 63곳이다.
- `API-명세`에는 17개가 있고, 코드에 없는 3개는 설계만 있는 것이다: `DELETE /polls/{pollId}`(#76), `POST /admin/polls/{pollId}/restore`와 `POST /admin/members/{memberId}/unsuspend`(#20). 코드에만 있고 `API-명세`에 없는 API는 없다.
- 새로 찾은 문서 오류: `02-투표-만들기`가 작성자 삭제 API를 구현된 것처럼 적고 있었다. 대조 검사가 첫 실행에서 찾았다.

## 어떤 순서로

1. 임시로 생성해 어노테이션과 `API-명세`의 API 목록을 대조 → 2. 생성 테스트 → 3. 문서 대조 검사와 테스트 → 4. 일부러 틀린 문서로 잡히는지 확인 → 5. 문서 정리와 이 sketch

## 지킬 규칙

API를 더하거나 바꾸면 같은 PR에서 `DOCS_UPDATE=1 ./gradlew test --tests '*OpenApiDocTest'`로 파일을 다시 만든다(안 하면 빌드가 실패한다). 새 API는 기능 페이지의 "사용하는 API"에도 적는다(안 하면 `docs-check`가 실패한다).

## 막아야 할 것

- 파일이 실행마다 달라지는 것: 키 순서를 고정하고 서버 주소를 뺐다. 반복 실행해도 같은 결과임을 확인했다.
- 기능 페이지가 존재하지 않는 API를 적는 것: 검사가 막는다.

## 한계

- 어노테이션의 설명이 맞는지(의미)는 사람이 본다. 필드를 바꾸면 `openapi.json`의 diff로 리뷰에서 보인다.
- 서버 없이 보는 화면(정적 뷰어)은 만들지 않았다. 다음 PR 이후에 게시한다.
