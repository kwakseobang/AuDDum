# 낡은 안내 문구를 정리하고 용어집을 도메인 모델에서 뺀다

## 왜 하나

문서 개편 뒤 전체 리뷰에서 이미 낡은 문장이 나왔다. 끝난 단계를 "2단계에서 옮겨 온다"처럼 예정으로 적은 README, 없어진 API 명세서를 기준으로 삼는 개발 워크플로 문장, 아무도 고치지 않는 머리표(버전·작성일·작성자), `index.md` 정본 표의 중복 행이다. 도메인 모델(28KB)은 비개발자가 용어만 찾기에 길어서 용어집을 따로 뺀다(#99에서 `domain/`에 도메인 모델과 용어집을 두기로 했다).

## 무엇을 건드리나

- 고친다: `docs/` 폴더 README 4개, 다이어그램 README, 개발 워크플로 3장, 문서 머리표 12곳과 제목, `index.md`, `CLAUDE.md` 문서 지도, `auddum-conventions` 절 색인
- 만든다: `docs/domain/용어집.md`
- 하지 않는다: SVG 최신 검사, ERD 생성·검사(#114에서 미뤘다), 기능 페이지 내용

## 어떻게 할까

| 질문 | 결정 | 이유 |
|---|---|---|
| 머리표 | 버전·작성일·작성자를 지우고 관련 문서만 한 줄로 남긴다 | 손으로 고쳐야 하는 값이라 곧 틀린다. 언제 누가 바꿨는지는 git과 sketch가 맡는다 |
| 제목 | `AuDDum` 접두어와 "설계서"를 뗀다 | 기능 페이지와 같은 모양으로 맞춘다. 파일 이름과 제목이 같아야 찾기 쉽다 |
| 용어집 | 도메인 모델 1장을 그대로 옮기고 도메인 모델의 절 번호를 하나씩 당긴다 | 말뜻을 찾는 사람은 용어집만, 구현하는 사람은 도메인 모델만 읽으면 된다 |
| 절 번호 참조 | `auddum-conventions`의 `도메인-모델.md §n`을 절 이름으로 바꾼다 | 번호가 밀리면 조용히 틀린다. #99의 "§ 번호는 쓰지 않는다"를 따른다 |
| 다이어그램 한계 | "3단계에서 정한다"를 "CI가 확인하지 않는다, `.d2`를 고치면 같은 커밋에서 SVG를 다시 만든다"로 바꾼다 | #114에서 미루기로 이미 정했다. 미뤘다는 사실과 사람이 지킬 규칙을 적는다 |

## 결과

- 머리표 12곳을 한 줄로 바꾸고 제목을 맞췄다. 옛 이름("ERD 설계", "아키텍처 설계서")이 남은 링크 문구도 함께 고쳤다.
- `domain/용어집.md`를 만들고 `index.md`, `CLAUDE.md`, 컨벤션, ERD, 지원 스킬의 링크를 옮겼다.
- 개발 워크플로 3장에서 없어진 명세서를 기준으로 삼던 두 문장을 고치고, 이미 정한 springdoc 버전 확인 문장을 지웠다.
- 한계: 끝난 일을 "예정"으로 남기는 문장은 사람이 찾아야 한다. 검사로 막지 않았다.
