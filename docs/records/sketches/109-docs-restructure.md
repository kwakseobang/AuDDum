# 폴더 정리와 사용자-시나리오 폐지

## 왜 하나

기능 페이지 7개가 UC 17개와 정책 28건을 모두 가져가서, 남은 문서를 역할별 폴더(`domain/`, `engineering/`, `product/`, `howto/`)로 옮기고 입구를 `index.md` 하나로 합칠 수 있게 됐다. 이슈 #109의 세 번째 PR이다.

## 무엇을 건드리나

- 옮긴다: `도메인-모델` → `domain/`, `아키텍처`·`설계-결정`·`예외-정책`(`예외-응답`으로 개명) → `engineering/`, `PRD`·`로드맵` → `product/`, `README` → `index.md`
- 나눈다: `인증-중복-참여`, `개발-가이드`, `테스트-배포`
- 없앤다: `사용자-시나리오`
- 고친다: 하네스(`.claude`, `CLAUDE.md`)의 문서 경로와 색인, `docs-check`(정의 파일 경로, 링크 검사, 퇴역 이름 검사)
- 건드리지 않는다: `API-명세`, `ERD`(3단계에서 생성 문서로 바꾼다), 코드

## 어떻게 할까

사용자와 정한 것(2026-10-29):

| 질문 | 결정 |
|---|---|
| PR을 쪼갤까 | 한 PR로 하고 커밋만 나눈다(이동, 분할, 입구·폐지, 하네스 경로, 검사, sketch) |
| `인증-중복-참여`의 검증 테스트 표 11행 | 참여 관련 7행은 `03-참여하기`로, 나머지 4행은 `동시성-중복-방지`에 둔다 |
| 하네스 | 경로와 문서 색인만 고친다. 절 번호(§)는 4단계에서 정리한다 |

- `git mv`로 옮겨 이력을 보존했다. 분할은 가장 큰 쪽을 `git mv`하고 나머지를 새로 만들었다.
- 옮긴 뒤 상대 링크 51곳은 스크립트로 다시 계산했다. 분할한 문서에서 나온 링크 6곳은 손으로 고쳤다.
- `사용자-시나리오`의 남은 내용은 요약(핵심 규칙 5개)과 서비스 흐름도는 `index.md`로, 작성 전제는 `features/README.md`로 옮겼다. UC 목록 표는 `index.md`의 기능 지도로 바꿨다.
- 퇴역 이름 검사는 `docs/records/`(시점 기록)를 제외한다. 과거 sketch가 옛 이름을 쓰는 것은 맞는 기록이다.

## 어떤 순서로

1. 이동과 링크 정리 → 2. 분할 → 3. `index.md`와 폐지 → 4. 하네스 경로 → 5. 검사 추가 → 6. 이 sketch
2. 각 단계에서 `docs-check`와 `test-docs-check`를 돌리고, 분할 뒤에는 원본의 모든 줄이 새 문서에 있는지 스크립트로 확인했다.

## 지킬 규칙

정의는 한 번만, 기능 페이지 이력과 sketch가 서로 링크, 코드 주석에 문서 이름을 쓰지 않는다. 옮긴 문서의 옛 이름은 `docs-check`가 잡는다.

## 막아야 할 것

- 분할하면서 줄을 잃는 것: 원본 줄을 새 문서 전체와 대조해 확인했다. 없는 줄은 의도한 것(제목·목차·요약 재작성, 검증 표 7행의 이동)뿐이었다.
- 옛 이름·옛 경로가 남는 것: 새로 만든 퇴역 이름 검사가 첫 실행에서 4곳(ERD, 도메인 모델, `CLAUDE.md` 이력)을 찾아냈다.
- 하네스가 틀린 경로를 읽는 것: `CLAUDE.md`의 문서 지도와 `auddum-conventions`의 문서 색인을 새로 썼다.

## 결과

- 문서 지도가 `index.md` 하나다. `CLAUDE.md`와 하네스는 이를 가리킨다.
- 검증 표 이동: `인증-중복-참여`의 참여 관련 7행은 `03-참여하기`의 '동시 요청과 경계에서 확인할 것'으로 갔다.
- 하네스의 절 번호 참조는 60곳(`.claude` 57, `CLAUDE.md` 3)에서 31곳(30, 1)으로 줄었다(문서를 옮기면서 사라진 것). 나머지는 4단계에서 정리한다.
- 한계: `API-명세`와 `ERD`는 아직 `docs/` 바로 아래에 있다. `index.md`의 문서 지도에 이유를 적었다. 문서 안의 Mermaid 18개는 다음 PR에서 D2로 바꾼다.
- 후속: PR 4(Mermaid → D2), 이후 3단계 생성 문서.
