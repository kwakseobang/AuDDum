# Mermaid를 D2로 바꾸고 읽기 쉽게 한다

## 왜 하나

폴더 정리(PR 3)가 끝났다. 남은 문서에는 Mermaid 그림 17개가 있고(ERD의 1개는 3단계), 개발자만 아는 말이 풀이 없이 나온다. 그림을 D2로 모으고, 비개발자도 첫 문장에서 길을 잃지 않게 한다. 이슈 #109의 마지막 PR이다.

## 무엇을 건드리나

- 바꾼다: `index`, `로드맵`, `도메인-모델`(4개), `아키텍처`(3개), `인증`(2개), `동시성-중복-방지`, `배포`(2개), `개발-워크플로`의 Mermaid 17개를 `docs/diagrams/`의 D2·SVG로
- 고친다: `PRD`, `로드맵`, `도메인-모델`, `아키텍처`, `인증`, `동시성-중복-방지`, `배포`, `테스트-전략`의 요약 문장과 용어 풀이
- 건드리지 않는다: `API-명세`, `ERD`(3단계), 코드, 사실(정책·규칙·숫자)

## 어떻게 할까

| 질문 | 결정 |
|---|---|
| PR을 쪼갤까 | 한 PR로 하고 커밋만 나눈다(그림 변환, 읽기 정리, sketch) |
| 상태 전이도 | 상자와 화살표로 그린다(시작 상자를 따로 둔다) |
| 클래스 그림 | 값 객체 9개는 한 상자로 묶고 포함·참조를 화살표로 구분한다(점선은 ID 참조) |
| gitGraph | 브랜치 종류 사이의 병합 방향을 보이는 그림으로 바꾼다(예시 커밋은 뺐다) |
| 읽기 정리 범위 | 요약 첫 문장을 쉬운 말로 바꾸고 용어는 처음 나올 때 풀이한다. 본문 구조는 이미 요약·표 중심이라 이번에 바꾸지 않았다 |

## 버린 안

- 문서별 전면 재작성: 사실이 바뀔 위험이 크고 대조 비용이 크다. 필요해지면 문서별 이슈로 따로 한다.

## 원문 대조표

사실은 바뀌지 않았다. 바뀐 문장만 적는다.

| 문서 | 원문 | 바뀐 뒤 | 종류 |
|---|---|---|---|
| PRD | 모놀리스로 만들어 | 서버 프로그램 하나(Spring Boot 모놀리스)로 만들어 | 풀이 추가 |
| PRD | 카카오 OAuth | 카카오 계정으로 하고(OAuth) | 풀이 추가 |
| PRD | DB 제약조건과 트랜잭션 | 각각 괄호 풀이 추가 | 풀이 추가 |
| PRD | 커서 기반 페이징, 모놀리식 구조 | 괄호 풀이 추가 | 풀이 추가 |
| PRD | 시나리오·예외 명세서와 ERD 문서 | 기능 페이지와 ERD 링크 | 옛 이름 고침 |
| 로드맵 | `develop`에 병합 가능한 단위, DoD | 풀이 추가 | 풀이 추가 |
| 인증·동시성·아키텍처·배포·테스트 전략·도메인 모델 | 요약 첫 문장 | 쉬운 말로 다시 씀 | 표현만 변경 |
| 17개 문서 안 그림 | Mermaid 블록 | 그림 파일 링크와 원본 링크 | 형식 변경 |

## 한계

- 새 SVG는 임시 글꼴이다(3단계에서 정한다).
- 요약 밖의 본문 읽기 쉬움은 이번에 손대지 않았다. 비개발자 독자 테스트로 어디가 어려운지 확인한 뒤 고친다.
