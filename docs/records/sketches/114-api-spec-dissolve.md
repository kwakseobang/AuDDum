# 손으로 쓴 API 명세를 없애고 생성 문서와 공통 규칙으로 옮긴다

## 왜 하나

`API-명세`(469줄)는 코드를 손으로 옮겨 쓴 문서라 코드와 어긋날 수 있다. 앞선 PR에서 코드가 정본인 사실(오류 코드, API 목록, 요청·응답 필드)을 코드에서 만들고 기능 페이지와 대조하게 했다. 이제 손으로 쓴 명세는 같은 내용을 두 번 쓰는 문서라 없앤다. 협업자가 있다고 보고, 사람이 읽는 곳(API 목록, 공통 규칙)을 먼저 만든 뒤 지웠다. 이슈 #114의 마지막 PR이다.

## 무엇을 건드리나

- 만든다: `engineering/API-공통-규칙.md`
- 옮긴다: 카카오 로그인 설명 → `engineering/인증.md` 3절
- 더한다: `04-결과-보기`(결과 전용 API 없음), `06-관리자-조치`(본문 형식 오류), `개발-워크플로`(생성 문서를 다시 만드는 법, 새 API는 문서와 빈 메서드를 먼저 올려 합의)
- 없앤다: `docs/API-명세.md`. 링크하던 문서·하네스는 새 위치로 고쳤다
- 고친다(검사): `docs-check`의 퇴역 이름에 `API-명세`를 더했다

## 어떻게 할까

| 질문 | 결정 | 이유 |
|---|---|---|
| 엔드포인트별 요청·응답 표와 JSON 예시 | 없앤다. `openapi.json`이 대신한다 | 필드는 `@Schema`의 설명·예시로 코드에 있다. 손으로 쓴 표가 낡는 쪽이다 |
| 공통 규칙과 오류 응답 형식 | 새 문서 `API-공통-규칙` | 스웨거에 담기지 않는 규칙이고, 협업자가 API를 쓸 때 가장 먼저 읽는다 |
| 카카오 로그인 | `인증` 3절 | 컨트롤러가 없고 필터가 처리해서 `openapi.json`에 안 나온다. 인증 문서가 이미 토큰·쿠키를 다룬다 |
| 설계만 있는 API 3개 | 따로 옮기지 않는다 | `02`·`06`의 "사용하는 API"에 "구현 전"으로 있고 규칙(R-POLL-14 등)과 시나리오가 기능 페이지에 있다. 구현할 때 문서 클래스를 먼저 만든다 |
| 새 API를 미리 보이게 하려면 | 문서 클래스와 빈 메서드(501)만 먼저 PR(개발 워크플로에 적음) | 구현 전에 `openapi.json`에 나타나 프런트가 먼저 개발할 수 있다 |

## 원문 대조표

`API-명세`의 344개 문장(줄을 문장으로 나눈 것)을 기계로 걸러 본 결과다. 같은 내용이 다른 문서·어노테이션·코드에 있는지 핵심어(코드 이름, 숫자, 낱말)로 찾아서, 겹침이 낮은 47개를 한 문장씩 보고 겹침이 높지만 빠진 핵심어가 있는 60개를 따로 읽었다. 60개의 빠진 핵심어는 "하나이며", "호출하면"처럼 조사가 붙은 낱말의 형태 차이였고, 실제 사실은 모두 다른 곳에 있었다.

| 원문 | 새 위치 |
|---|---|
| 요약, 목차, 관련 문서 표 | 삭제. API 개수·영역은 `API 목록`이 맡는다 |
| 1절 공통 규칙 10행(기본 경로, 시각, 인증, 식별자 3개, 페이징, 득표율, 알 수 없는 필드, 멱등성) | `API-공통-규칙` 1절. "권한 표기" 행은 옛 문서의 용어 설명이라 뺐다 |
| 3절·6절의 목록 조회 `size` 보정, 빈 `cursor`, 형식 오류 400 | `API-공통-규칙`의 페이징 행(두 곳에 있던 같은 규칙을 한 곳으로) |
| 오류 응답 형식(필드 표, 예시), 인증·인가 실패의 구분 | `API-공통-규칙` 2·3절 |
| 2절 카카오 로그인 시작·콜백, `redirect`, state·세션, 실패 코드 표, 동시 첫 로그인 | `인증` 3절 |

## 어떤 순서로

1. 대조 → 2. 새 문서와 인증 절 → 3. 링크 약 40곳 교체 → 4. 하네스 문서 교체 → 5. 명세 삭제와 `docs-check` 통과 → 6. 이 sketch

## 지킬 규칙

API를 바꾸면 `openapi.json`과 API 목록을 다시 만들고(빌드가 확인), 기능 페이지의 "사용하는 API"와 규칙을 같이 고친다. API의 사실을 손으로 적는 문서를 새로 만들지 않는다.

## 막아야 할 것

- 사라지는 문장: 위 대조로 확인했다. 새 문서로 옮긴 문장은 원문 그대로 옮겼다.
- 링크가 깨지는 것: `docs-check`의 깨진 링크 검사와 퇴역 이름 검사로 확인했다.
- 에이전트가 없는 문서를 읽는 것: `domain-reviewer`·`test-writer`·`auddum-conventions`의 참조를 새 문서로 바꿨다.

## 한계

- 기계로 걸러 본 것은 핵심어가 있는 문장이라, 핵심어 없이 뜻만 다른 곳에 옮겨진 경우는 못 거른다. 그런 문장은 사람이 읽는 47개에 포함되도록 기준을 낮게 잡았다.
- 필드 설명의 의미는 `openapi.json`의 어노테이션에 있고, 맞는 말인지는 사람이 본다.
