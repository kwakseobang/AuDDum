# 사실 정본 2 — 기능 페이지의 오류 코드·테스트 이름을 코드와 대조

## 왜 하나

모든 팀원이 기능 페이지 한 곳을 보고, 그 문서가 코드와 어긋나면 사람이 기억하지 않아도 자동으로 잡히게 하려는 것이 3단계의 목표다. 기능 페이지의 규칙 표에는 오류 코드와 상태(`409 ALREADY_VOTED`), 테스트 클래스 이름(`VoteTest`)이 손으로 적혀 있어 코드가 바뀌면 조용히 낡는다. 이슈 #114의 두 번째 PR이다.

## 무엇을 건드리나

- 만든다: `docs-check`의 기능 페이지 사실 대조(오류 코드·상태, 테스트 클래스 이름), 테스트 2개 묶음(10여 개 확인)
- 고친다: `index`의 `docs-check` 설명, PRD 머리의 역할 한 줄과 `index`의 PRD 설명
- 하지 않는다: 테스트에 `@Tag`를 다는 것

## 어떻게 할까

| 질문 | 결정 | 이유 |
|---|---|---|
| 테스트 추적을 어떻게 하나 | `@Tag`를 달지 않고 문서에 적은 테스트 클래스 이름이 `src/test`에 있는지만 본다(사용자 결정, 2026-10-30) | 테스트 수십 개를 고치지 않고도 "테스트를 지우거나 이름을 바꾸면 문서가 낡는" 문제를 잡는다. 테스트가 없는 규칙은 "테스트 아직 없음"으로 이미 드러난다 |
| 코드는 어떻게 읽나 | `src/main`에서 `implements ErrorCode`인 파일의 `NAME (HttpStatus.X, …)` 줄을 읽는다 | 컴파일 없이 `docs-check`(Java 단일 파일)가 돈다. 오류 코드 표를 만드는 테스트와 같은 원본이다 |
| 어디를 검사하나 | 기능 페이지의 `409 \`CODE\`` 꼴(어느 줄이든), 표의 둘째 칸(어긋나면)의 오류 코드 이름, `\`XxxTest\`` 꼴 | 지금 페이지가 쓰는 형식 그대로라서 문서를 고치지 않는다 |
| 아직 없는 코드는 | 같은 줄에 "구현 전"이라고 적으면 넘어간다 | `MEMBER_NOT_SUSPENDED`처럼 #20에서 구현할 코드가 있다. 구현하면 그 말을 지우게 된다 |
| PRD | 목표·범위·대상·지표만 갱신하고 세부 정책은 기능 페이지가 최신이라고 머리에 적는다 | 기획서는 시점의 소스이고 정본은 기능 페이지다(사용자와 정리, 2026-10-30) |

## 어떤 순서로

1. 실제 저장소에 돌려 오탐이 없는지 확인(첫 실행에서 없음) → 2. 테스트 작성 → 3. 기능 페이지의 상태를 일부러 틀리게 해서 잡히는지 확인하고 되돌림 → 4. 문서 설명 → 5. 이 sketch

## 지킬 규칙

기능 페이지에 오류 코드나 테스트 클래스를 적을 때는 이 형식(`409 \`CODE\``, `\`XxxTest\``)을 쓴다. 다른 표기로 적으면 검사가 못 본다.

## 막아야 할 것

- 오탐으로 CI가 막히는 것: 현재 저장소에서 오류 0건을 확인했다. 앞으로 생길 오탐은 "구현 전" 표기나 형식 수정으로 푼다.
- 검사가 아무것도 안 보는 것: 오류 코드 enum이나 테스트가 없는 저장소는 해당 검사를 건너뛰는데(도구 시험용), 실제 저장소에서는 20개 코드와 95개 테스트 클래스를 읽는다. 기능 페이지의 상태를 일부러 틀리게 해서 잡히는 것을 확인했다.
