# 기능 페이지

기능 하나가 어떻게 동작하는지 이 폴더의 페이지 하나로 읽는다. 흐름, 규칙, 실패 응답, 테스트 위치가 한곳에 있다.

| 항목 | 내용 |
|---|---|
| 파일 이름 | `NN-기능이름.md` (스토리맵 순서) |
| 양식 | [`_양식.md`](_양식.md). 필수 절은 한눈에·흐름·이럴 때는·이력이고, 규칙·정책 정의·사용하는 API는 해당할 때만 둔다 |
| 시나리오·정책 정의 | 기능 페이지로 옮긴 UC·P 정의는 여기가 정본이다. UC는 `이럴 때는` 표의 첫 칸, P는 `정책 정의` 표의 첫 칸이 정의다 |
| 규칙과 정책 | 규칙(R)은 코드가 항상 지키는 조건이고, 정책(P)은 그렇게 정한 제품 결정이다. 규칙 정의는 도메인 모델 문서에 있고 여기는 한 문장 요약만 둔다 |
| 이력 | 이력 표와 [sketch](../records/sketches)가 서로 링크한다(docs-check가 확인) |

## 작성 원칙

모든 문서에 적용하는 원칙은 [index.md](../index.md)의 "읽기 쉽게 쓰는 원칙"에 있다. 기능 페이지는 거기에 아래를 더한다.

| 원칙 | 내용 |
| --- | --- |
| 한계는 한 곳 | 막을 수 없는 것은 `한눈에`의 **한계**에만 쓰고 다른 절에서 되풀이하지 않는다 |
| 응답 코드 위치 | 응답 코드는 `흐름`과 `규칙`에만 쓴다. `이럴 때는`에는 쓰지 않는다 |
| ID는 문장 끝 | UC·P·R 번호는 문장 끝 괄호나 맨 끝 칸에 둔다. 정의를 세는 표의 첫 칸(UC·P)만 예외다 |

## 기능 페이지의 전제

모든 기능 페이지에 공통으로 깔려 있는 전제다. 페이지마다 되풀이하지 않는다.

- 모든 검증은 서버가 수행한다. 프런트엔드의 버튼 비활성화는 검증이 아니다.
- 비회원 쿠키는 신원 확인 수단이 아니라 중복 참여를 줄이는 보조 수단이다. 쿠키 삭제나 다른 기기 사용까지 막을 수 없다.
- 페이지의 HTTP 상태 코드는 읽기 위한 요약이다. 정확한 코드와 상태는 [오류 코드](../generated/오류-코드.md)와 [API 목록](../generated/API-목록.md)이 기준이다.
- 예외 상황의 응답은 각 페이지의 "이럴 때는"과 규칙 표에 있고, 오류 코드 전체는 [오류 코드 표](../generated/오류-코드.md)에 있다.
