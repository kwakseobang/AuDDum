## 1. 로컬 개발 환경

### 준비물

- Java 25 (Liberica), Docker
- 저장소의 `gradlew`로 빌드한다. Gradle toolchain이 Java 25를 요구한다.

### 구성

- `compose.yaml`에 MySQL 8.4(`mysql` 서비스, 데이터베이스 `auddum`)를 둔다. Spring Boot가 `spring-boot-docker-compose`로 앱 기동 때 함께 올려 준다. 호스트 포트는 **3307**이다. 다른 프로젝트의 MySQL이 3306을 쓰는 경우가 많아 피했다.
- 프로파일은 `local`(로컬 MySQL)과 `prod`(RDS)로 나누고 파일도 나눈다. 기본 프로파일은 `local`이다. ([배포](배포.md)의 환경 설정과 비밀 값)

  | 파일(`src/main/resources/`) | 내용 |
  | --- | --- |
  | `application.yaml` | 공통(앱 이름, JPA, KST, 소셜 로그인 클라이언트 등록, 프런트 주소). 기본값을 두지 않는다. |
  | `application-local.yaml` | 로컬 MySQL 접속, `.env`를 읽는다. |
  | `application-prod.yaml` | RDS 접속(환경 변수만 사용), Swagger UI와 `/v3/api-docs`를 끈다. 운영에서는 `KAKAO_CLIENT_ID`, `KAKAO_CLIENT_SECRET`, `JWT_SECRET`, `ANON_COOKIE_SECRET`, `FRONTEND_BASE_URL`이 필수라 값이 없으면 기동하지 못한다. |

- 테스트는 H2를 쓴다. `src/test/resources/application.yaml`이 메인 설정을 대신하므로 테스트에서는 `local`·`prod` 파일이 읽히지 않는다.
  - 다만 동시 참여 테스트(`VoteConcurrencyTest`)는 Testcontainers의 MySQL 8.4 컨테이너를 쓰므로 `./gradlew test`·`build`에는 Docker가 켜져 있어야 한다.
- 비밀 값(카카오 클라이언트 id·secret, JWT 서명 키, 익명 쿠키 HMAC 키, DB 비밀번호)은 코드와 git에 넣지 않는다.
  - 로컬은 `.env` 또는 환경 변수로 주입하고, `.env`는 `.gitignore`에 넣는다. 샘플은 `.env.example`로 커밋한다.
  - `application-local.yaml`에는 비밀 값 없이 `${DB_PASSWORD}` 같은 환경 변수 참조만 둔다.
- 시각은 KST를 기준으로 한다. `spring.jpa.properties.hibernate.jdbc.time_zone: Asia/Seoul`과 커넥션 초기화 `SET time_zone = '+09:00'`(`spring.datasource.hikari.connection-init-sql`)로 JPA와 DB 접속을 맞춘다.

### 로컬 실행

1. `cp .env.example .env` 후 `DB_PASSWORD`, `DB_ROOT_PASSWORD`를 채운다.
   - 카카오 로그인을 확인하려면 `KAKAO_CLIENT_ID`, `KAKAO_CLIENT_SECRET`(카카오 개발자 콘솔의 REST API 키와 시크릿)도 채우고, 콘솔의 리다이렉트 URI에 `http://localhost:8080/login/oauth2/code/kakao`를 등록한다.
   - 로컬(`local` 프로파일)에서는 값이 없어도 앱은 뜨지만 카카오 로그인은 실패한다.
   - 로그인 뒤 이동할 프런트 주소는 `FRONTEND_BASE_URL`이고 로컬 기본값은 `http://localhost:3000`이다. 이 주소의 origin 말고 CORS·Origin 검사에서 더 허용할 origin은 선택 환경 변수 `CORS_ALLOWED_ORIGINS`(쉼표 구분)에 둔다.
   - JWT 서명 키는 `JWT_SECRET`(32바이트 이상)이고 로컬 기본값이 있다.
   - 인증 쿠키의 Secure 속성은 `auddum.auth.cookie-secure`로 정하며 기본은 true이고 로컬(http)만 false다.
2. `./gradlew bootRun` — compose가 MySQL을 먼저 올리고 앱이 뜬다. 앱을 끄면 컨테이너도 함께 내려간다.
3. `curl http://localhost:8080/actuator/health`가 `{"status":"UP"}`이면 기동한 것이다. 8080을 다른 앱이 쓰면 `SERVER_PORT=18080 ./gradlew bootRun`처럼 포트를 바꾼다.

### 의존성

`build.gradle.kts`에 아래를 추가했다.

- `spring-boot-starter-security`, `spring-boot-starter-oauth2-client`, `spring-boot-starter-validation`, `spring-boot-starter-actuator`
- springdoc-openapi, Flyway(`flyway-core`, `flyway-mysql`), MySQL 드라이버, JWT(JJWT), 테스트용 ArchUnit

버전은 Spring Boot 의존성 관리를 따른다. 관리 밖인 springdoc-openapi·JJWT·ArchUnit만 `build.gradle.kts`에서 버전을 직접 정한다.

## 2. DB 마이그레이션

> [!WARNING]
> 이미 병합된 마이그레이션 파일은 고치지 않고 새 파일을 추가한다. 주석 한 줄만 바꿔도 체크섬이 달라져 앱이 기동하지 못한다.

- Flyway로 스키마를 관리하고 위치는 `src/main/resources/db/migration`이다.
- 파일 이름은 `V{번호}__{설명}.sql`이다. 예: `V1__init_schema.sql`
- `V1`에 [ERD](../ERD.md)의 테이블 8개, 제약조건, 인덱스를 옮긴다.
- 공통 설정은 `ddl-auto=validate`(엔티티와 스키마가 어긋나면 기동 실패)이고, 테스트는 `none`이라 H2도 같은 Flyway SQL로만 스키마를 만든다.
- H2에서 도는 문법만 쓴다. 막히는 부분은 해당 부분만 자동 생성으로 내린다. ([배포](배포.md)의 환경 설정과 비밀 값)

## 3. 카카오 개발자 앱 등록

| 항목 | 내용 |
| --- | --- |
| 앱 | 개발용과 운영용을 **따로** 만들어 키를 분리한다. |
| 리다이렉트 URI(로컬) | `http://localhost:8080/login/oauth2/code/kakao` |
| 리다이렉트 URI(운영) | `https://api.도메인/login/oauth2/code/kakao` |
| 동의 항목 | 카카오 고유 식별자만 쓴다. 닉네임·프로필·이메일은 저장하지 않으므로 받지 않는다. |
| 비밀 값 | 클라이언트 id·secret은 환경 변수로 주입한다. |

## 4. 관리자 계정 부여

관리자 권한은 API로 바꿀 수 없고 DB에서 직접 부여한다. ([ERD](../ERD.md))

> [!WARNING]
> 운영 DB에 SQL을 직접 실행한다. 누가 언제 바꿨는지 작업 기록(이슈 또는 PR 코멘트)에 남긴다.

- 먼저 카카오 로그인으로 **일반 회원으로 가입**한 뒤, 운영 DB에서 `role`을 `ADMIN`으로 직접 바꾼다.
- 이 SQL은 마이그레이션에 넣지 않고 수동으로 실행한다.
- 관리자는 초기에 1명이다. 늘릴 때도 같은 절차를 따른다.
- 관리자 권한은 요청마다 DB의 `role`로 확인한다(토큰의 `role`은 권한 판단에 쓰지 않는다). ([인증](../engineering/인증.md))
