## 1. 영속성

- **조회 방식.** 단순 조회는 Spring Data 파생 메서드를 쓴다. 이름이 너무 길어지거나 fetch join·bulk delete처럼 파생 메서드로 안 되는 경우에만 JPQL `@Query`를 쓴다.
- **네이티브 쿼리.** 네이티브 쿼리는 쓰지 않는다. H2 테스트와 호환되지 않는다(`테스트-전략.md`).
- **bulk 쿼리.** bulk delete·update(`@Modifying`)에 `clearAutomatically`를 쓰지 않는다.
- **캐시.** 캐시는 성능 문제가 측정되기 전에는 두지 않는다. 회원 상태 조회도 같다.

## 2. 동시성

- **동시성 제어.** 투표 참여의 동시성은 DB 유니크 제약으로 막고 락을 쓰지 않는다. (#16)
- **MySQL 검증.** 실제 MySQL 동작은 Testcontainers(`mysql:8.4`) 통합 테스트로 확인한다. 같은 컨테이너를 쓰는 테스트는 `MySqlConcurrencyTestSupport`를 상속한다. `anon_id` CHAR(36) 매핑도 여기서 확인한다. 도메인과 상관없는 테스트 기반(`IntegrationTestSupport`, `DataIntegrationTestSupport`, `MySqlConcurrencyTestSupport`, `ConcurrentRace`)은 테스트 최상위 패키지(`org.kwakmunsu.auddum`)에 두고, 도메인 테스트가 다른 도메인의 테스트 패키지를 import하지 않는다. (#17, #92)
- **테스트 분리.** 이 테스트는 태그나 별도 Gradle task로 나누지 않고 일반 `./gradlew test`에 포함한다. Docker가 필요하고, 시간이 문제가 되면 그때 분리한다. (#17)

## 3. 코드 관행

**시간**

- **현재 시각.** 현재 시각은 `LocalDateTime.now(TimeConfig.KST)` 형태로만 만들고 시스템 기본 시계(`now()`)는 쓰지 않는다. 컨트롤러가 만들어 넘기는 곳(`PollWebApi`, `AuthWebApi`)도 있고, vote 서비스는 요청당 한 번 읽어 구현 클래스에 내린다. (#16)
- **시간 변환.** 시간 변환은 `TimeConfig`(KST)를 쓴다. 테스트 코드도 포함하되, 판정에 쓰이지 않는 픽스처 값은 차단이 아니라 권고로 다룬다.

**도메인 모델**

- **상태 기반 판단.** 열람 가능 여부, "정상 상태의 관리자" 같은 상태 기반 판단은 서비스나 `*Reader`가 아니라 도메인 객체(`Poll`, `Member`)가 한다. DB 조회가 필요한 값(관리자 여부)은 `BooleanSupplier` 같은 지연 평가로 넘긴다. (#54, #56)
- **Voter·AnonId.** `Voter`(회원 ID 또는 `AnonId` 중 정확히 하나)와 `AnonId`는 `@Embeddable` record이고 컬럼 이름(`member_id`, `anon_id`)을 값 객체가 가진다. `Vote`는 `@Embedded Voter`만 둔다. (#15)
- **값 객체 공유.** `Vote`와 `Report`는 값 객체를 공유하지 않는다. 같은 모양이어도 애그리거트마다 의미와 규칙이 달라질 수 있다. 신고는 자기 값 객체 `Reporter`를 둔다(`report`는 `vote`에 의존할 수 없다). 익명 쿠키의 발급·검증·해석(`AnonCookieProvider`, `AnonIdentityResolver`)은 UUID만 다루는 `support.anon`에 두어 vote와 report가 함께 쓰고, 쿠키 값을 `AnonId`(vote)나 `Reporter`(report)로 감싸는 일은 각 도메인이 한다. (#15, #60)
- **AnonId 생성자.** `AnonId`의 public 생성자는 열어 둔다. "서명 검증을 통과한 값만 만든다"는 구조로 강제하지 않고 코드 관행으로 지킨다. DB 복원 경로에도 생성자가 필요하고 쓰는 곳이 `VoterResolver`와 `Vote` 둘뿐이다. 쓰는 곳이 늘면 다시 정한다. (#15)
- **도메인 이벤트.** 도메인 이벤트는 회원 탈퇴(`MemberWithdrawnEvent`)에만 도입했다. 새 이벤트를 늘릴 때는 이 문서를 먼저 고친다.

**투표 참여 (vote)**

- **동시 요청의 패자.** 동시 요청에서 진 쪽은 선택이 같아도 409 `ALREADY_VOTED`이고 재조회하지 않는다. 겹치는 구간이 같은 순간에 사전 조회를 통과한 요청뿐이고, 재조회를 위한 트랜잭션 분리가 과하다. (#16)
- **제약 위반 변환.** 유니크 제약 위반만 409로 바꾸고(`VoteWriter`) 외래키·CHECK 위반은 500이다. 이미 참여한 사람의 요청은 사전 조회에서 409이고 재전송 200은 두지 않는다. (#16)
- **쿠키 속성.** 익명 쿠키의 Secure 속성은 `auddum.auth.cookie-secure`를 따른다. 오류로 끝난 요청에서는 새로 발급한 쿠키도 내리지 않는다. (#16)
- **서비스 인자.** 서비스가 받는 인자는 개념별 record로 묶는다: 어느 투표의 몇 번 선택지인지는 `PollChoice`, 요청한 사람의 신원 단서(회원 ID, 익명 쿠키)는 `VoterCredential`이다. 값 검증은 넣지 않는다(형식은 투표 조회, 범위는 도메인이 한다). `VoterCredential`은 vote의 것이고 신고는 자기 인자 record `ReporterCredential`을 둔다. (#16, #60, #18)
- **구현 클래스 참조.** 구현 계층 클래스끼리의 참조는 허용한다. 한 클래스가 한 가지 일을 하게 하고 필요해질 때만 나눈다. (#16)
- **위조 쿠키 로그.** 위조 익명 쿠키는 `AnonIdentityResolver`가 WARN으로 남기고 `reason`(형식 오류, 서명 불일치)만 적는다. 쿠키 원문은 남기지 않는다. 빈 문자열 쿠키는 쿠키 없음으로 본다. (#15)

**신고 접수 (report)**

- **신고자 결정.** `ReporterResolver`가 회원 확인(정지 403, 탈퇴·없음 401) 뒤 `Reporter`로 감싼다. 쿠키 해석(유효하면 UUID, 없거나 위조면 발급, 위조 WARN)은 `VoterResolver`와 함께 `support.anon.AnonIdentityResolver`를 쓴다. `support`는 도메인을 모르므로 회원 상태 확인과 `Voter`/`Reporter` 포장은 각 도메인이 한다. (#18)
- **투표 조회.** 신고 대상은 `PollReader.getPublic(publicId)`로 읽는다. 공개가 아닌 투표(숨김·삭제)는 작성자·관리자도 404다. 마감 투표는 신고할 수 있다. 조회자를 `null`로 넘기는 `getReadable`은 쓰지 않는다. 투표 참여도 같은 `getPublic`으로 읽는다(검증 1단계 "존재하고 공개 상태"와 같다). (#18, #93)
- **상세 저장.** `ETC`가 아닌 사유에 담긴 `detail`도 버리지 않고 입력 그대로 저장한다. 상한 200자(유니코드 문자 단위)는 사유와 상관없이 적용하고 앞뒤 공백은 자르지 않는다. 사유는 요청에서 `ReportReasonCode` enum으로 받고, 허용되지 않은 값은 본문 형식 오류(400 `MALFORMED_REQUEST`)다. 사유 누락과 상세 규칙 위반은 400 `VALIDATION_FAILED`다. (#18)
- **중복 신고.** 사전 조회(`ReportValidator`)가 빠른 409를 주고, 동시 요청에서 진 쪽은 `ReportWriter`가 유니크 제약 위반을 409 `REPORT_ALREADY_SUBMITTED`로 바꾼다. 투표 참여와 같은 구조다. (#18)
- **`submit`에 `now`가 없다.** 접수 시각은 `createdAt` 자동 채움이 맡고, 신고 접수에는 시각으로 판단하는 규칙이 없다(마감과 무관). 처리 시각은 `dismiss`가 받는다. (#18)
- **Reader를 두지 않는 경우.** 신고의 중복 확인은 쓰는 곳이 `ReportValidator` 하나뿐이라 `Reader` 없이 repository를 직접 쓴다. 읽는 곳이 늘면 그때 나눈다. (#18)

**관리자 신고 조회 (admin)**

- **조합 위치.** 관리자 신고 목록·상세는 admin의 사용 사례이고 컨트롤러·DTO·서비스(`AdminReportQueryService`)도 admin에 둔다. 신고는 `ReportReader`, 투표는 `PollReader`(상태 무관 `find`·`findAllByIds`)로 읽고 서비스끼리는 부르지 않는다. 서비스 첫 단계에서 `AdminAccessValidator`를 부른다. (#19)
- **목록 정렬과 집계.** 접수 순(id 오름차순)이고 커서는 마지막 신고 id다. 상태와 무관하게 같다. 투표별 신고 수(`pollReportCount`)는 처리된 신고도 센다. 페이지의 투표 ID `IN` + `GROUP BY` 한 번이다. (#19)
- **상세의 다른 신고 상한.** 상세의 `otherReports`는 접수 순 처음 20건까지만 담는다(`ReportReader.OTHER_REPORTS_LIMIT`). 익명 신고는 쿠키를 지우면 새 신고자가 되어 한 투표에 제한 없이 쌓일 수 있고, 상한이 없으면 신고를 열 때마다 모두 읽고 직렬화한다. 도배 방어가 정해지면 다시 본다. (#19)
- **신고 조치의 동시성.** 관리자는 한 명이라 서로 다른 관리자의 경쟁은 없고, 같은 요청이 동시에 두 번 들어오는 경우(더블클릭·재전송)를 막는 것은 신고 기각뿐이다. 투표 숨김·삭제와 회원 정지의 더블클릭은 막지 않아 이력이 두 건 남을 수 있다(상태는 같은 값이라 틀어지지 않는다). `Report`에 낙관적 락(`@Version`)을 걸고 `Report.dismiss`가 PENDING을 확인한다. 읽은 뒤 다른 요청이 먼저 처리하면 `ReportWriter.saveHandled`가 즉시 flush해 충돌을 잡고 409 `REPORT_ALREADY_HANDLED`로 바꾼다. 투표 행·신고 행 잠금은 쓰지 않는다. 같은 투표의 서로 다른 신고를 동시에 처리하는 경쟁은 관리자가 늘면 다시 본다(데드락 가능성이 있다). (#19)
- **조치 API는 별도 기능이다.** 신고 기각, 투표 숨김·삭제, 회원 정지를 각각 하나의 목적을 가진 API로 둔다. 숨김과 삭제는 대상(투표)·흐름·부수 효과가 같고 바뀌는 상태만 달라서 한 API(`PATCH /admin/polls/{id}/status`, `status` enum)로 합쳤다. 조치 조합 검증(기각 단독, 숨김과 삭제 배타 등)이 필요 없고 신고 없이 직접 정지할 수 있다. 투표 숨김·삭제는 같은 트랜잭션에서 그 투표의 대기 신고를 모두 RESOLVED로, 기각은 같은 투표의 대기 신고를 모두 DISMISSED로 종료한다. 회원 정지는 신고 상태를 바꾸지 않는다. 한 신고에 숨김과 정지를 이어서 하는 것은 요청이 둘이라 원자적이지 않다(관리자가 한 명이라 감수한다). 이력의 `reportId`는 기각에만 채우고, 신고 상세의 `actions`는 이 신고의 기각 이력과 대상 투표에 한 숨김·삭제 이력을 담는다. (#19)
- **조치 서비스의 모양.** 조치 서비스(`AdminReportCommandService`, `AdminPollCommandService`, `AdminMemberCommandService`)는 권한 확인, 대상 읽기, 도메인 행위, 저장, 이력 기록의 흐름만 둔다. 이미 목표 상태인 대상은 건너뛰지 않고 409로 알린다(`POLL_NOT_PUBLIC`, `MEMBER_NOT_ACTIVE`, `REPORT_ALREADY_HANDLED`). 처리한 신고의 저장과 같은 투표의 다른 대기 신고 종료는 `ReportWriter`가 맡는다. 사유는 권한 확인 뒤에 `AdminAction`이 검증하므로 권한 오류(403)가 사유 오류(400)보다 먼저 나간다. (#19)
- **도메인 이벤트 없음.** 신고 조치(숨김·삭제·정지)에는 도메인 이벤트를 도입하지 않는다. 정지 회원도 로그인·재발급이 가능하고 상태는 쓰기마다 DB로 확인해(P-22) 토큰을 폐기할 이유가 없으며, 작성자 알림은 MVP 범위 밖이다. 이력은 같은 트랜잭션에서 직접 기록한다. (#19)
- **일괄 종료.** 같은 투표의 다른 PENDING 신고는 bulk update로 한 번에 같은 결과로 종료한다(`updatedAt`은 직접 갱신). 낙관적 락 버전도 직접 올려, 낡게 읽은 다른 요청이 충돌로 걸리게 한다. 회원 정지는 작성자 행을 잠그지 않으므로, 같은 회원의 동시 탈퇴와 겹치면 `Member`가 전체 컬럼을 갱신해 정지가 탈퇴 상태를 덮어쓸 수 있다(낮은 확률). 발생이 확인되면 행 잠금이나 `@DynamicUpdate`를 검토한다. 관리자가 자기 자신을 정지하는 것을 막는 규칙은 두지 않았다(#20에서 복구 절차와 함께 정한다). (#19)
- **커서 중복.** 관리자 신고 커서(`ReportCursor`)는 poll의 `PollCursor`와 모양이 같아도 따로 둔다. 도메인마다 커서 의미(정렬 방향·키)가 달라질 수 있다. (#19)

**투표 조회와 조합 (poll)**

- **목록·상세 위치.** 투표 목록과 상세는 poll의 사용 사례이고 컨트롤러·DTO·서비스도 poll에 둔다. 다른 도메인의 데이터는 poll이 선언한 포트로 받는다. 방식과 바뀔 수 있다는 점은 `아키텍처.md`의 '애플리케이션 구조'에 있는 조회 조합 규칙이다. (#62, #63)
- **포트 범위.** 포트 `ParticipationReader`는 poll의 화면에 필요한 값으로 좁게 두고 필요가 생길 때만 늘린다(목록의 참여 수, 상세의 내 선택·득표). 계약은 "요청한 모든 투표 ID를 키로 가진 맵"이고, 참여가 없으면 0, 입력이 비면 빈 맵이며 0 채우기는 구현(vote)이 한다. (#62)
- **참여 수 집계.** 참여 수는 페이지의 투표 ID `IN` + `GROUP BY poll_id` 한 번으로 센다. 카운터 컬럼과 캐시는 두지 않고, 조회 최적화 인덱스는 MVP 이후 측정한 뒤 정한다. (#62)
- **상세의 시각 판단.** 상세는 서비스가 요청 시각 하나로 마감과 결과 공개(`Poll.isResultOpen`)를 판단하고, vote는 사실(내 선택 순번, 선택지별 득표)만 돌려준다. (#63)
- **조회자 신원.** 조회하는 사람의 신원 단서는 poll의 `Viewer`(회원 ID, 익명 쿠키 값)이다. poll은 쿠키 값을 해석하지 않고 해석은 vote의 `VoterResolver`가 한다. (#63)
- **쿠키 이름 상수.** 쿠키 이름 상수 `AnonCookieName`과 쿠키 쓰기 `AnonCookies`는 `support.web`에, 발급·검증은 `support.anon`에 둔다. (#63, #60)
- **결과 DTO 위치.** `PollTally`·`OptionTally`·`PollResultResponse`는 poll에 있고 참여 응답(vote)도 쓴다. (#63)
- **다른 도메인의 투표 읽기.** 다른 도메인의 투표 읽기는 `PollQueryService`가 아니라 `PollReader`(poll.application)로 한다. 열람 가능한 투표 한 건(`getReadable`), 공개된 투표 한 건(`getPublic`), 공개 투표 목록(`findPublicOlderThan`)을 맡는다. (#63, #18)

**구현 계층 이동 (#63)**

- **재사용 감지.** 폐기 여부·유예 판단(재사용 감지)은 읽은 엔티티가 필요해 `RefreshTokenService`에 남긴다. 토큰 규칙이 늘면 구현 클래스로 옮긴다.
- **토큰 해시.** 리프레시 토큰의 SHA-256 해시는 `RefreshTokenReader`·`RefreshTokenWriter`가 `RefreshTokenHash`로 처리해서 서비스는 원문만 다룬다.
- **트랜잭션 위치.** `@Transactional`(`noRollbackFor` 포함)과 비관적 잠금(`findForUpdate`)은 서비스에 두고, 구현 클래스는 트랜잭션 경계 없이 서비스의 트랜잭션에 참여한다.
- **소셜 로그인 어댑터.** 소셜 로그인 어댑터(`OAuth2LoginUserService`, `@ApplicationService` 아님)가 `MemberCommandService`를 부르는 것은 서비스 규칙의 대상이 아니다.
- **트랜잭션 ArchUnit.** 구현 계층 `@Component`에 `@Transactional`을 금지하는 ArchUnit 규칙은 두지 않는다. "자체 트랜잭션 경계를 두지 않는다"는 문서 규칙으로 충분하다. (#63)

## 4. 알려진 한계 (고치지 않기로 한 것)

- 같은 회원의 동시 탈퇴, `reissue`와 탈퇴의 경합에는 락을 걸지 않는다. (#17)
- 쓰기 서비스가 `getActiveMember`를 빠뜨리는 실수는 구조로 막지 않고 리뷰 항목으로 둔다.
- `reissue`의 10초 유예는 폐기 사유와 무관하게 적용한다.
- 만료된 리프레시 토큰 행 정리는 아직 없다.
- 쿠키 값은 컨트롤러가 `@CookieValue`로 받아 서비스에 넘긴다. 신고 API(#18)까지 두 곳이라 웹 계층 `ArgumentResolver`로 모으지 않았고, 세 번째 사용처가 생기면 다시 정한다.
- 위조 익명 쿠키를 반복해서 보내면 WARN이 그만큼 늘어난다. 운영에서 빈도가 문제가 되면 그때 정한다.
