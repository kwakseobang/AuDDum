# 도메인 모델

관련 문서: [용어집](용어집.md), [동시성·중복 방지](../engineering/동시성-중복-방지.md), [ERD](../ERD.md), [아키텍처](../engineering/아키텍처.md)

## 요약

AuDDum(어떰)이 다루는 개념(회원·투표·참여·신고·관리자 조치)과 그 규칙을 애그리거트(함께 바뀌는 데이터 묶음) 단위로 정리했다. 애그리거트는 회원(Member), 투표(Poll), 참여(Vote), 신고(Report), 관리자 조치(AdminAction) 다섯 개다. 각 애그리거트의 속성, 행위, 규칙과 상태 열거형, 값 객체(VO)를 적었다. 용어의 뜻과 영문 이름은 [용어집](용어집.md)에 있다.

- 규칙은 도메인 객체가 지키고, 서비스는 흐름과 트랜잭션만 맡는다. ([아키텍처](../engineering/아키텍처.md))
- 애그리거트 사이는 객체가 아니라 ID로만 참조한다.
- 행위 이름과 값 객체 구성은 지금 코드와 같다. 코드에서 이름을 바꾸면 이 문서도 같은 PR에서 고친다. 테이블과 제약은 ERD 문서가 기준이다.
- 규칙에는 `R-<애그리거트>-<번호>` 번호가 있다. 굵게 쓴 곳(`**R-POLL-nn**`)이 정의이고 괄호로 쓴 곳(`(R-POLL-nn)`)은 참조다. 번호는 한 번 붙이면 바꾸지 않는다.

## 2. 회원 애그리거트

### 회원 (Member)

> 가입한 사용자의 **상태와 로그인 정보**를 소유한다. 정지·탈퇴 규칙을 이 객체가 지킨다.

`Aggregate Root`

| 속성 | 타입 | 설명 |
| --- | --- | --- |
| `id` | `Long` | 식별자 |
| `status` | `MemberStatus` | 회원 상태 |
| `role` | `Role` | 권한. API로 바꿀 수 없다. |
| `lastLoginAt` | `LocalDateTime` | 마지막 로그인 일시 |
| `suspendedAt` | `LocalDateTime` | 정지 일시 (정지 전에는 null) |
| `withdrawnAt` | `LocalDateTime` | 탈퇴 일시 (탈퇴 전에는 null) |
| `createdAt`, `updatedAt` | `LocalDateTime` | 생성·수정 일시 |
| `refreshTokens` | `RefreshToken` | 리프레시 토큰 - 회원당 여러 건 (동시 로그인 허용) |

| 행위 | 설명 |
| --- | --- |
| `static signUp()` | **R-MEMBER-01** 회원 가입. 상태를 ACTIVE, 권한을 MEMBER로 둔다. |
| `recordLogin(now)` | 마지막 로그인 일시를 저장한다. |
| `suspend(now)` | **R-MEMBER-02** 이용 정지. ACTIVE일 때만 SUSPENDED로 바꾸고 정지 일시를 기록한다. 이미 정지·탈퇴한 회원이면 409 `MEMBER_NOT_ACTIVE`다. |
| `unsuspend()` | 정지 해제 |
| `withdraw(now)` | 탈퇴. 상태와 탈퇴 일시를 바꾼다. 소셜 연동 정보는 서비스가 같은 트랜잭션에서 삭제한다(MemberAuth는 회원을 참조하는 별도 엔티티라 회원이 목록으로 갖지 않는다). 리프레시 토큰은 서비스가 발행한 `MemberWithdrawnEvent`를 auth가 같은 트랜잭션에서 받아 삭제한다. |
| `isActive()` | 정상 상태인가? |
| `validateActive()` | 정상 상태인지 점검한다. 정지·탈퇴이면 거절한다. **R-MEMBER-11** (정지 회원이 할 수 있는 쓰기는 로그아웃·탈퇴·토큰 재발급뿐이라 이 셋은 호출하지 않는다. 탈퇴와 재발급은 탈퇴한 회원만 401로 거절한다.) |
| `validateNotWithdrawn()` | 탈퇴한 회원이면 거절한다(401). 정지 회원은 통과한다. 탈퇴·재발급·내 정보 조회가 쓴다. |
| `isAdmin()` | role이 ADMIN인가? |
| `hasAdminAuthority()` | **R-MEMBER-10** 관리자 권한이 있는가? role이 ADMIN이고 정상(ACTIVE)이어야 한다. 정지·탈퇴한 관리자는 없다. |

회원이 지키는 규칙:

- **R-MEMBER-05** 탈퇴해도 작성한 투표는 그대로 둔다(`authorId`는 남고, 일반 사용자 응답에는 작성자를 내지 않는 것이 익명화다). 참여 기록은 보존하며 결과 집계에 계속 반영한다.
- 같은 소셜 계정으로 다시 가입하면 이전 회원과 연결되지 않는 새 회원이 만들어진다. (R-MEMBER-07)
- **R-MEMBER-08** 같은 사람이 다른 제공자(예: 카카오와 구글)로 로그인하면 별개의 회원이다. 계정 연결·병합은 지원하지 않는다(이메일을 수집하지 않고, 미검증 이메일로 병합하면 계정 탈취 위험이 있다). 필요해지면 로그인한 회원이 직접 연동을 추가하는 방식을 따로 설계한다.
- **R-MEMBER-03** 정지는 기간 없이 수동으로 해제할 때까지 유지한다.
- **R-MEMBER-09** 관리자 권한은 API가 아니라 DB에서 직접 부여한다. role은 API로 바꿀 수 없다.

### 회원 상태 (MemberStatus)

`Enum`

| 상수 | 의미 |
| --- | --- |
| `ACTIVE` | 정상 |
| `SUSPENDED` | 정지 |
| `WITHDRAWN` | 탈퇴 |

| 전이 | 행위자 | 규칙 |
| --- | --- | --- |
| ACTIVE → SUSPENDED | 관리자 | 이용 정지. 기간 없이 수동으로 해제할 때까지 유지한다. (R-MEMBER-03, P-13) |
| SUSPENDED → ACTIVE | 관리자 | **R-MEMBER-04** 정지 해제 |
| ACTIVE → WITHDRAWN | 본인 | 탈퇴. 연동 정보와 리프레시 토큰을 삭제하고, 작성 투표는 익명화해 유지하며 참여 기록은 보존한다. (R-MEMBER-05, P-04) |
| SUSPENDED → WITHDRAWN | 본인 | **R-MEMBER-06** 정지 중에도 탈퇴할 수 있다. 정지 회피 목적의 탈퇴·재가입은 한계로 명시한다. (P-14) |
| WITHDRAWN → 없음 | — | **R-MEMBER-07** 되돌릴 수 없다. 같은 소셜 계정으로 다시 가입하면 새 회원이다. (P-14) |

`Enum`

### 소셜 연동 (MemberAuth)

`Entity`

| 속성 | 타입 | 설명 |
| --- | --- | --- |
| `id` | `Long` | 식별자 |
| `provider` | `AuthProvider` | 연동 제공자. 지금은 KAKAO뿐이고 제공자를 늘릴 때 열거형과 클라이언트 설정에 추가한다. `Natural ID` |
| `providerUserId` | `String` | 제공자의 고유 식별자(카카오 id, 구글 sub 등) `Natural ID` |
| `createdAt`, `updatedAt` | `LocalDateTime` | 생성·수정 일시 (`BaseEntity`가 자동으로 채운다) |

소셜 연동이 지키는 규칙:

- **R-MEMBER-12** (provider, providerUserId)는 유일하다. 같은 소셜 계정은 하나의 회원에만 연결된다.
- **R-MEMBER-13** 회원을 식별하는 정보는 이 엔티티에만 두고 Member에는 두지 않는다.
- **R-MEMBER-14** 탈퇴하면 삭제한다.

### 리프레시 토큰 (RefreshToken)

`Entity`

| 속성 | 타입 | 설명 |
| --- | --- | --- |
| `id` | `Long` | 식별자 |
| `memberId` | `Long` | 토큰 주인 회원의 ID (회원 엔티티를 참조하지 않는다) |
| `tokenHash` | `String` | 토큰 해시값 (원문은 저장하지 않는다) |
| `expiresAt` | `LocalDateTime` | 만료 일시 (발급 후 14일) |
| `revokedAt` | `LocalDateTime` | 폐기 일시 (폐기 전에는 null) |
| `createdAt`, `updatedAt` | `LocalDateTime` | 생성·수정 일시 |

| 행위 | 설명 |
| --- | --- |
| `issue(memberId, tokenHash, expiresAt)` | 발급 |
| `revoke(now)` | 폐기. 이미 폐기됐으면 처음 폐기한 시각을 유지한다. |
| `isRevoked()` | 폐기된 토큰인가? |
| `isWithinGrace(now)` | 폐기 후 10초 이내(정확히 10초 포함)인가? 폐기되지 않았으면 false |

만료는 토큰(JWT `exp`)이 판단하므로 엔티티는 만료를 판단하지 않는다. `expiresAt`은 기록용이다.

리프레시 토큰이 지키는 규칙:

- **R-MEMBER-15** 재발급할 때마다 새 토큰을 만들고 이전 토큰은 폐기한다.
- **R-MEMBER-16** 폐기된 토큰이 다시 오면(재사용) 그 회원의 토큰을 모두 폐기한다. 단, 폐기 후 **10초 이내**의 동시 재발급은 허용한다.
- **R-MEMBER-17** 로그아웃은 현재 기기의 토큰만 폐기하고, 탈퇴는 모두 삭제한다.

## 3. 투표 애그리거트

### 투표 (Poll)

> 질문과 선택지, 마감, 공개 상태를 소유한다. **마감 판단과 상태 전이**는 이 객체의 책임이다.

`Aggregate Root`

| 속성 | 타입 | 설명 |
| --- | --- | --- |
| `id` | `Long` | 내부 식별자. 외부에 노출하지 않는다. |
| `publicId` | `PublicId` | 공개 ID `Natural ID` |
| `authorId` | `Long` | 작성자 회원 ID (탈퇴해도 유지) |
| `question` | `PollQuestion` | 질문 |
| `category` | `Category` | 카테고리 |
| `status` | `PollStatus` | 공개 상태 |
| `closesAt` | `ClosesAt` | 마감 시각 (없으면 마감 없는 투표) |
| `createdAt`, `updatedAt` | `LocalDateTime` | 생성·수정 일시 |
| `options` | `PollOption` | 선택지 - 2~5개 |

| 행위 | 설명 |
| --- | --- |
| `static create(authorId, question, category, options, closesAt, now)` | 투표 생성. 상태를 PUBLIC으로 두고 공개 ID를 부여한다. |
| `validateCreatableAfter(latest, now)` | 같은 작성자의 직전 투표 뒤에 만들 수 있는지 점검한다. 질문이 같으면 `DUPLICATE_POLL`, 직전 생성 후 30초가 지나지 않았으면 `POLL_RATE_LIMITED`이고 둘이 겹치면 `DUPLICATE_POLL`이 우선한다. |
| `isClosed(now)` | 마감되었는가? 서버 시각이 마감 시각 이상이면 마감이다. |
| `isPublic()` | 공개 상태인가? |
| `validateVotable(now)` | **R-POLL-20** 참여 가능 상태(공개이면서 마감 전)인지 점검한다. |
| `getOption(position)` | 이 투표의 선택지를 찾아 돌려준다. 없으면 `INVALID_OPTION`이다. |
| `positionOf(optionId)` | 선택지 id의 순번을 돌려준다. |
| `isResultOpen(participated, now)` | **R-POLL-19** 결과를 보여 줄 수 있는가? 마감되었거나 참여했으면 공개다(P-03·P-25). |
| `hide()` | 관리자 숨김. 공개 투표만 숨길 수 있다. 이미 숨겨졌으면 409 `POLL_NOT_PUBLIC`, 삭제됐으면 404 `POLL_NOT_FOUND`다. (R-POLL-12) |
| `restore()` | 숨김 복구 |
| `deleteByAuthor(memberId)` | 작성자 삭제 |
| `deleteByAdmin()` | 관리자 삭제 |
| `isAuthor(memberId)` | 작성자인가? |

투표가 지키는 규칙:

| ID | 대상 | 규칙 |
| --- | --- | --- |
| **R-POLL-01** | 질문·카테고리 | 질문은 앞뒤 공백을 제거한 뒤 **1~500자**(유니코드 문자 단위)이고 줄바꿈이 없다. 줄바꿈은 `\n`, `\r`, `\u000B`, `\u000C`, `\u0085`, `\u2028`, `\u2029`를 말한다. 앞뒤의 줄바꿈은 공백 제거로 사라지고 중간의 줄바꿈은 거부한다. 카테고리는 필수다. |
| **R-POLL-02** | 선택지 | **2~5개**이고 앞뒤 공백을 제거한 뒤 각 **1~50자**(유니코드 문자 단위)이며, 줄바꿈이 없고(질문과 같은 문자) 서로 중복될 수 없다. 제거한 값을 저장하고, 대소문자와 악센트를 구분하지 않고 비교한다. |
| **R-POLL-03**, **R-POLL-04** | 연속 생성 | 같은 작성자는 직전 투표(삭제·숨김 포함)와 같은 질문(앞뒤 공백 제거 후, 대소문자 구분)을 만들 수 없고, 직전 생성 후 30초가 지나야 다시 만들 수 있다. |
| **R-POLL-05** | 마감 시각 | 선택이다. 있으면 생성 시점(now)보다 뒤여야 하고(같은 시각도 거부) 상한은 없다. |
| **R-POLL-06** | 수정·삭제 | 생성 후 질문·선택지·마감 시각은 수정할 수 없다. 작성자는 삭제만 할 수 있다. |
| **R-POLL-07** | 마감 판단 | **마감은 저장하지 않고 계산한다**(P-11). 판단에 쓰는 now는 요청 시점에 한 번 정해 넘긴다. 목록·상세·참여에서 누가 now를 정하는지는 [아키텍처](../engineering/아키텍처.md)의 "마감 시각과 판단의 위치"에 있다. |
| **R-POLL-08** | 검증 실패 | 값 객체나 생성 규칙을 어기면 `VALIDATION_FAILED`이고, 어느 필드가 왜 틀렸는지(`field`, `reason`)를 `errors`에 담는다(요청 검증이 먼저 걸러도 도메인이 한 번 더 지킨다). |

- **R-POLL-09** 숨김은 관리자만 하고, 관리자가 숨긴 투표는 작성자가 삭제할 수 없다.
- **R-POLL-10** 신고가 쌓여도 처리 전까지는 PUBLIC을 유지한다. 건수만으로 자동 처리하지 않는다.
- **R-POLL-11** 작성자를 정지해도 그 회원의 기존 투표는 그대로 둔다.
- **R-POLL-21** 공개 ID(PublicId)는 12자 영숫자이고 생성 시 중복이면 다시 발급한다. 내부 `id`는 외부에 노출하지 않는다.

### 공개 상태 (PollStatus)

`Enum`

| 상수 | 의미 |
| --- | --- |
| `PUBLIC` | 공개 |
| `HIDDEN` | 숨김 |
| `DELETED` | 삭제 |

| 전이 | 행위자 | 규칙 |
| --- | --- | --- |
| PUBLIC → HIDDEN | 관리자 | **R-POLL-12** 신고 검토 결과 숨김. 공개 투표만 숨길 수 있고, 이미 숨겨졌으면 409 `POLL_NOT_PUBLIC`이다. |
| PUBLIC → DELETED | 작성자, 관리자 | **R-POLL-13** 작성자 삭제(UC-17) 또는 관리자 삭제 |
| HIDDEN → PUBLIC | 관리자 | **R-POLL-14** 복구. 숨김이 아니면 409 `POLL_NOT_HIDDEN`이다. |
| HIDDEN → DELETED | 관리자 | **R-POLL-15** 관리자가 삭제한다. 관리자가 숨긴 투표는 작성자가 삭제할 수 없다(R-POLL-09, P-30). |
| DELETED → 없음 | — | **R-POLL-16** 삭제는 되돌릴 수 없다. 숨김만 관리자가 복구할 수 있다. (P-01) |

전이를 어기면 이 오류로 거절한다.

- 삭제된 투표에 하는 숨김·삭제: `POLL_NOT_FOUND` (R-POLL-16)
- 숨김이 아닌 투표의 복구: `POLL_NOT_HIDDEN` (R-POLL-14)
- 숨김 투표를 작성자가 삭제: `POLL_NOT_DELETABLE` (R-POLL-09)
- **R-POLL-17** 작성자가 아닌 사람의 삭제: 공개 투표면 `FORBIDDEN`, 숨김·삭제 투표면 존재를 숨기려고 `POLL_NOT_FOUND`(P-01)

## 4. 참여 애그리거트

### 참여 (Vote)

> 한 참여자가 한 투표에서 고른 선택의 **불변 기록**이다. 중복 참여는 DB 유니크 제약이 마지막으로 막는다.

`Aggregate Root`

| 속성 | 타입 | 설명 |
| --- | --- | --- |
| `id` | `Long` | 식별자 |
| `pollId` | `Long` | 투표 ID `Natural ID` |
| `optionId` | `Long` | 선택지 ID |
| `voter` | `Voter` | 참여자 (회원 ID 또는 익명 식별자) `Natural ID` |
| `createdAt`, `updatedAt` | `LocalDateTime` | 참여·수정 일시 |

| 행위 | 설명 |
| --- | --- |
| `static cast(poll, position, voter, now)` | 참여 기록 생성. 투표가 참여 가능한지(공개·마감 전)와 선택지 소속을 확인한 뒤 만든다. |

참여가 지키는 규칙:

- **R-VOTE-01** 생성 후 변경·삭제할 수 없다. 선택을 바꾸는 방법은 없다.
- **R-VOTE-02** 한 참여자는 한 투표에 한 번만 참여한다(투표 + 참여자). DB 유니크 제약이 최종 방어선이다.
- **R-VOTE-03** 참여자는 회원 ID와 익명 식별자 중 정확히 하나다.
- **R-VOTE-04** 선택지는 반드시 같은 투표의 선택지여야 한다. DB 복합 외래키로도 보장한다.
- **R-VOTE-05** 같은 참여자가 다시 보내면 선택과 관계없이 409 `ALREADY_VOTED`다. 마감 후에도 같다(P-12).
- **R-VOTE-06** 정지 회원은 참여할 수 없다.
- **R-VOTE-07** 탈퇴한 회원의 참여 기록은 보존하며 집계에 반영한다.
- **R-VOTE-08** 비회원 참여 기록과 회원 ID는 연결하지 않는다.

## 5. 신고 애그리거트

### 신고 (Report)

> 부적절한 투표에 대한 **접수와 처리 상태**를 소유한다.

`Aggregate Root`

| 속성 | 타입 | 설명 |
| --- | --- | --- |
| `id` | `Long` | 식별자 |
| `pollId` | `Long` | 신고 대상 투표 ID `Natural ID` |
| `reporter` | `Reporter` | 신고자 (회원 ID 또는 익명 식별자) `Natural ID` |
| `reason` | `ReportReason` | 신고 사유 |
| `status` | `ReportStatus` | 신고 상태 |
| `createdAt`, `updatedAt` | `LocalDateTime` | 접수·수정 일시 |
| `handledAt` | `LocalDateTime` | 처리 일시 (처리 전에는 null) |
| `version` | `Long` | **R-REPORT-08** 낙관적 락 버전. 같은 신고에 조치가 동시에 들어오면 한쪽만 반영한다. |
| `handledBy` | `Long` | 처리한 관리자 ID (처리 전에는 null) |

| 행위 | 설명 |
| --- | --- |
| `static submit(pollId, reporter, reason)` | **R-REPORT-01** 신고 접수. 상태를 PENDING으로 둔다. 접수 시각은 `createdAt`이 자동으로 채운다. |
| `dismiss(adminId, now)` | 기각. PENDING일 때만 DISMISSED로 바꾸고 처리 일시·처리자를 기록한다. 이미 처리된 신고면 409 `REPORT_ALREADY_HANDLED`. 숨김·삭제 때의 RESOLVED 종료는 이 행위가 아니라 서비스의 일괄 갱신이다(R-REPORT-06). |
| `isPending()` | 처리 대기 상태인가? |

신고가 지키는 규칙:

- **R-REPORT-02** 한 신고자는 한 투표를 한 번만 신고할 수 있다(투표 + 신고자). 중복 신고는 한 건만 인정한다.
- **R-REPORT-03** 사유는 허용된 5가지뿐이다. `ETC`일 때 상세 텍스트는 필수다(공백뿐이면 없는 것). 다른 사유에 담긴 상세는 버리지 않고 입력 그대로 저장한다. 상한은 사유와 상관없이 200자(임시, 유니코드 문자 단위)다.
- **R-REPORT-05** 종료된 신고는 다시 처리할 수 없다. 상태 전이는 신고 상태 절에 있다.
- 같은 투표의 PENDING 신고는 한 번의 조치로 함께 종료한다. (R-REPORT-06)
- **R-REPORT-04** 숨김·삭제된 투표에는 신고할 수 없다. 정지 회원은 신고할 수 없다.

## 6. 관리자 조치 애그리거트

### 관리자 조치 (AdminAction)

> 관리자가 한 조치의 **추가 전용 이력**이다.

`Aggregate Root`

| 속성 | 타입 | 설명 |
| --- | --- | --- |

| `adminId` | `Long` | 조치한 관리자 회원 ID |
| `type` | `ActionType` | 조치 종류 |
| `targetPollId` | `Long` | 대상 투표 ID (투표 조치와 신고 기각일 때) |
| `targetMemberId` | `Long` | 대상 회원 ID (회원 조치일 때) |

| --- | --- |

관리자 조치가 지키는 규칙:

- **R-ACTION-01** 추가만 가능하고 수정·삭제하지 않는다.
- **R-ACTION-02** 모든 조치에 처리자, 처리 시각, 조치 내용, 사유를 남긴다. 사유는 필수이고 1~200자다.
- **R-ACTION-03** 대상 상태 변경, 신고 상태 변경, 이력 기록은 한 트랜잭션으로 처리한다. 실패하면 전부 롤백한다.

## 7. 값 객체

식별자가 없고 값 자체로 같음을 판단하며, 만들 때 규칙을 검증하는 개념이다. 불변으로 두며 Java `record`로 작성하고 compact constructor에서 검증한다. 값 객체를 써도 DB 컬럼은 바뀌지 않는다(엔티티에 임베디드로 매핑).

| VO | 소속 | 담는 값 | 만들 때 검증하는 규칙 |
| --- | --- | --- | --- |
| PublicId | Poll | 12자 영숫자 문자열 | R-POLL-21 |
| PollQuestion | Poll | 질문 문자열 | R-POLL-01 |
| OptionContent | PollOption | 선택지 문자열 | R-POLL-02 (서로 달라야 한다는 규칙은 Poll이 확인한다) |
| Position | PollOption | 순번 | R-POLL-22 |
| ClosesAt | Poll | 마감 시각(선택) | R-POLL-05, R-POLL-07 |
| AnonId | Vote | UUID | 서명 검증을 통과한 값만 만든다. 쿠키 발급·검증은 `support.anon`이 UUID로 하고, 신고자는 `AnonId`가 아니라 UUID를 직접 가진다. |
| Voter | Vote | 회원 ID 또는 AnonId | R-VOTE-03 (참여의 "같은 참여자" 판단에 쓴다) |
| Reporter | Report | 회원 ID 또는 익명 식별자 | 둘 중 정확히 하나. 신고의 "같은 신고자" 판단에 쓴다. `Voter`와 별개의 값 객체다. 익명 식별자는 UUID를 직접 가진다. |
| ReportReason | Report | 신고 사유 코드(ReportReasonCode)와 `ETC` 상세 | R-REPORT-03 |

상태값(PollStatus, MemberStatus, ReportStatus)과 Category는 enum이다. 전이 규칙은 해당 엔티티의 메서드가 지키고, 각 애그리거트 절의 상태 표에 있다.
