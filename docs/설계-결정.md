## 1. 영속성

- 단순 조회는 Spring Data 파생 메서드를 쓴다. 이름이 너무 길어지거나 fetch join·bulk delete처럼 파생 메서드로 안 되는 경우에만 JPQL `@Query`를 쓴다.
- 네이티브 쿼리는 쓰지 않는다. H2 테스트와 호환되지 않는다(`테스트-배포.md`).
- bulk delete·update(`@Modifying`)에 `clearAutomatically`를 쓰지 않는다.
- 캐시는 성능 문제가 측정되기 전에는 두지 않는다. 회원 상태 조회도 같다.

## 2. 동시성

- 투표 참여의 동시성은 DB 유니크 제약으로 막고 락을 쓰지 않는다. (#16)
- 실제 MySQL 동작은 Testcontainers(`mysql:8.4`) 통합 테스트로 확인한다. 같은 컨테이너를 쓰는 테스트는 `MySqlConcurrencyTestSupport`를 상속한다. `anon_id` CHAR(36) 매핑도 여기서 확인한다. (#17)
- 이 테스트는 태그나 별도 Gradle task로 나누지 않고 일반 `./gradlew test`에 포함한다. Docker가 필요하고, 시간이 문제가 되면 그때 분리한다. (#17)

## 3. 코드 관행

**시간**

- 현재 시각은 `LocalDateTime.now(TimeConfig.KST)` 형태로만 만들고 시스템 기본 시계(`now()`)는 쓰지 않는다. 컨트롤러가 만들어 넘기는 곳(`PollWebApi`, `AuthWebApi`)도 있고, vote 서비스는 요청당 한 번 읽어 구현 클래스에 내린다. (#16)
- 시간 변환은 `TimeConfig`(KST)를 쓴다. 테스트 코드도 포함하되, 판정에 쓰이지 않는 픽스처 값은 차단이 아니라 권고로 다룬다.

**도메인 모델**

- 열람 가능 여부, "탈퇴하지 않은 관리자" 같은 상태 기반 판단은 서비스나 `*Reader`가 아니라 도메인 객체(`Poll`, `Member`)가 한다. DB 조회가 필요한 값(관리자 여부)은 `BooleanSupplier` 같은 지연 평가로 넘긴다. (#54, #56)
- `Voter`(회원 ID 또는 `AnonId` 중 정확히 하나)와 `AnonId`는 `@Embeddable` record이고 컬럼 이름(`member_id`, `anon_id`)을 값 객체가 가진다. `Vote`는 `@Embedded Voter`만 둔다. (#15)
- `Vote`와 `Report`는 값 객체를 공유하지 않는다. 같은 모양이어도 애그리거트마다 의미와 규칙이 달라질 수 있다. 신고는 자기 값 객체 `Reporter`를 둔다(`report`는 `vote`에 의존할 수 없다). 쿠키 처리를 `vote` 밖으로 옮길지는 #60에서 정한다. (#15)
- `AnonId`의 public 생성자는 열어 둔다. "서명 검증을 통과한 값만 만든다"는 구조로 강제하지 않고 코드 관행으로 지킨다. DB 복원 경로에도 생성자가 필요하고 쓰는 곳이 `AnonCookieProvider`와 `Vote` 둘뿐이다. 쓰는 곳이 늘면 다시 정한다. (#15)
- 도메인 이벤트는 회원 탈퇴(`MemberWithdrawnEvent`)에만 도입했다. 새 이벤트를 늘릴 때는 이 문서를 먼저 고친다.

**투표 참여 (vote)**

- 동시 요청에서 진 쪽은 선택이 같아도 409 `ALREADY_VOTED`이고 재조회하지 않는다. 겹치는 구간이 같은 순간에 사전 조회를 통과한 요청뿐이고, 재조회를 위한 트랜잭션 분리가 과하다. (#16)
- 유니크 제약 위반만 409로 바꾸고(`VoteWriter`) 외래키·CHECK 위반은 500이다. 이미 참여한 사람의 요청은 사전 조회에서 409이고 재전송 200은 두지 않는다. (#16)
- 익명 쿠키의 Secure 속성은 `auddum.auth.cookie-secure`를 따른다. 오류로 끝난 요청에서는 새로 발급한 쿠키도 내리지 않는다. (#16)
- 서비스가 받는 인자는 개념별 record로 묶는다: 어느 투표의 몇 번 선택지인지는 `PollChoice`, 요청한 사람의 신원 단서(회원 ID, 익명 쿠키)는 `VoterCredential`이다. 값 검증은 넣지 않는다(형식은 투표 조회, 범위는 도메인이 한다). `VoterCredential`을 신고에서도 쓸지와 위치는 #60에서 정한다. (#16)
- 구현 계층 클래스끼리의 참조는 허용한다. 한 클래스가 한 가지 일을 하게 하고 필요해질 때만 나눈다. (#16)
- 위조 익명 쿠키는 WARN으로 남기고 `reason`(형식 오류, 서명 불일치)만 적는다. 쿠키 원문은 남기지 않는다. 빈 문자열 쿠키는 쿠키 없음으로 본다. (#15)

**투표 조회와 조합 (poll)**

- 투표 목록과 상세는 poll의 사용 사례이고 컨트롤러·DTO·서비스도 poll에 둔다. 다른 도메인의 데이터는 poll이 선언한 포트로 받는다. 방식과 바뀔 수 있다는 점은 `아키텍처.md` §2 조회 조합 규칙이다. (#62, #63)
- 포트 `ParticipationReader`는 poll의 화면에 필요한 값으로 좁게 두고 필요가 생길 때만 늘린다(목록의 참여 수, 상세의 내 선택·득표). 계약은 "요청한 모든 투표 ID를 키로 가진 맵"이고, 참여가 없으면 0, 입력이 비면 빈 맵이며 0 채우기는 구현(vote)이 한다. (#62)
- 참여 수는 페이지의 투표 ID `IN` + `GROUP BY poll_id` 한 번으로 센다. 카운터 컬럼과 캐시는 두지 않고, 조회 최적화 인덱스는 MVP 이후 측정한 뒤 정한다. (#62)
- 상세는 서비스가 요청 시각 하나로 마감과 결과 공개(`Poll.isResultOpen`)를 판단하고, vote는 사실(내 선택 순번, 선택지별 득표)만 돌려준다. (#63)
- 조회하는 사람의 신원 단서는 poll의 `Viewer`(회원 ID, 익명 쿠키 값)이다. poll은 쿠키 값을 해석하지 않고 해석은 vote의 `VoterResolver`가 한다. (#63)
- 쿠키 이름 상수 `AnonCookieName`은 컨트롤러가 읽을 수 있게 `support.web`에 두고, 발급·검증·속성은 vote에 남긴다. 위치는 #60에서 다시 본다. (#63)
- `PollTally`·`OptionTally`·`PollResultResponse`는 poll에 있고 참여 응답(vote)도 쓴다. (#63)
- 다른 도메인의 투표 읽기는 `PollQueryService`가 아니라 `PollReader`(poll.application)로 한다. 열람 가능한 투표 한 건(`getReadable`)과 공개 투표 목록(`findPublicOlderThan`)을 맡는다. (#63)

**구현 계층 이동 (#63)**

- 폐기 여부·유예 판단(재사용 감지)은 읽은 엔티티가 필요해 `RefreshTokenService`에 남긴다. 토큰 규칙이 늘면 구현 클래스로 옮긴다.
- 리프레시 토큰의 SHA-256 해시는 `RefreshTokenReader`·`RefreshTokenWriter`가 `RefreshTokenHash`로 처리해서 서비스는 원문만 다룬다.
- `@Transactional`(`noRollbackFor` 포함)과 비관적 잠금(`findForUpdate`)은 서비스에 두고, 구현 클래스는 트랜잭션 경계 없이 서비스의 트랜잭션에 참여한다.
- 소셜 로그인 어댑터(`OAuth2LoginUserService`, `@ApplicationService` 아님)가 `MemberCommandService`를 부르는 것은 서비스 규칙의 대상이 아니다.
- 구현 계층 `@Component`에 `@Transactional`을 금지하는 ArchUnit 규칙은 두지 않는다. "자체 트랜잭션 경계를 두지 않는다"는 문서 규칙으로 충분하다. (#63)

## 4. 알려진 한계 (고치지 않기로 한 것)

- 같은 회원의 동시 탈퇴, `reissue`와 탈퇴의 경합에는 락을 걸지 않는다. (#17)
- 쓰기 서비스가 `getActiveMember`를 빠뜨리는 실수는 구조로 막지 않고 리뷰 항목으로 둔다.
- `reissue`의 10초 유예는 폐기 사유와 무관하게 적용한다.
- 만료된 리프레시 토큰 행 정리는 아직 없다.
- 정지된 관리자를 관리자로 볼지는 관리자 API(#52)에서 정한다.
- `VoterResolver.resolve(memberId, cookieValue)`는 컨트롤러가 `@CookieValue`로 받은 값을 서비스에 넘기는 방식으로 쓴다. 웹 계층 `ArgumentResolver`로 모을지는 신고 API가 같은 결정을 쓰게 될 때(M5, #60) 다시 정한다.
- 위조 익명 쿠키를 반복해서 보내면 WARN이 그만큼 늘어난다. 운영에서 빈도가 문제가 되면 그때 정한다.
