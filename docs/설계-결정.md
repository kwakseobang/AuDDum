# 설계 결정과 코드 컨벤션

다른 docs에 없는, 이미 정한 결정과 코드 관행만 모은다. **리뷰어(code-reviewer, 내장 `/code-review` 포함)는 여기에 적힌 것을 다시 지적하지 않는다.** 바꾸고 싶으면 먼저 이 문서를 고치고 사용자 확인을 받는다.

이미 다른 문서에 있는 규칙은 여기에 옮겨 적지 않는다. 같은 규칙이 두 곳에 있으면 어긋난다.

## 1. 영속성

- 단순 조회는 Spring Data 파생 메서드를 쓴다. 메서드 이름이 너무 길어지거나, fetch join·bulk delete처럼 파생 메서드로 안 되는 경우에만 JPQL `@Query`를 쓴다. 네이티브 쿼리는 쓰지 않는다(H2 테스트와 호환, `테스트-배포.md`).
- bulk delete·update(`@Modifying`)에 `clearAutomatically`를 쓰지 않는다.
- 캐시는 성능 문제가 측정되기 전에는 두지 않는다(회원 상태 조회 포함).

## 2. 동시성

- 같은 회원의 동시 탈퇴, `reissue`와 탈퇴의 경합 같은 경합은 알려진 한계로 두고 락을 걸지 않는다. 투표 참여의 동시성은 DB 유니크 제약으로 막고 락을 쓰지 않으며, 실제 MySQL 동작은 Testcontainers(`mysql:8.4`) 통합 테스트로 확인한다. 태그나 별도 Gradle task로 나누지 않고 일반 `./gradlew test`에 포함한다(Docker 필요, 시간이 문제가 되면 그때 분리). `anon_id` CHAR(36) 매핑도 이 컨테이너에서 확인한다. 같은 MySQL 컨테이너를 쓰는 테스트는 `MySqlConcurrencyTestSupport`를 상속한다. (#17에서 확정)

## 3. 코드 관행

- 현재 시각은 `LocalDateTime.now(TimeConfig.KST)` 형태로만 만든다. 컨트롤러가 만들어 넘기는 곳(`PollWebApi`, `AuthWebApi`)이 있고, vote 서비스는 요청당 한 번 직접 읽어 구현 클래스에 내린다(#16에서 확정, 전체 관례는 #63에서 정한다). 시스템 기본 시계(`now()`)는 쓰지 않는다.
- 시간 변환은 `TimeConfig`(KST)를 쓴다. 테스트 코드도 포함하되, 판정에 쓰이지 않는 픽스처 값은 차단이 아니라 권고로 다룬다.
- 오류 비교는 `isInstanceOf(AuddumException.class).hasMessage(...)`로 한다(기준은 `auddum-conventions` 스킬 §2). 새로 쓰는 테스트가 이 방식이고, 기존 서비스 테스트의 `e.getErrorCode()` 비교는 그 파일을 손볼 때 바꾼다. 리뷰어는 기존 테스트의 `getErrorCode()`를 이번 변경과 무관하게 지적하지 않는다. (#15에서 `hasMessage`로 확정)
- 도메인 이벤트는 회원 탈퇴(`MemberWithdrawnEvent`)에만 도입했다. 새 이벤트를 늘릴 때는 이 문서를 먼저 고친다.

- 열람 가능 여부와 "탈퇴하지 않은 관리자" 같은 상태 기반 판단은 서비스나 `*Reader`가 아니라 도메인 객체(`Poll`, `Member`)가 한다. 서비스는 도메인 메서드를 부르고, DB 조회가 필요한 값(관리자 여부)은 `BooleanSupplier` 같은 지연 평가로 넘긴다. (#54 시범 리뷰 CR-1·CR-2에서 확정, #56에서 `Poll.isReadableBy`·`Member.hasAdminAuthority`로 옮겼다.)

- 참여자: `Voter`(회원 ID 또는 `AnonId` 중 정확히 하나)와 `AnonId`는 `@Embeddable` record이고 컬럼 이름(`member_id`, `anon_id`)을 VO가 가진다. `Vote`는 `@Embedded Voter`만 둔다. 같은 모양이어도 애그리거트마다 의미와 규칙이 달라질 수 있어서 `Vote`와 `Report`는 값 객체를 공유하지 않는다. 신고는 자기 값 객체 `Reporter`를 둔다(`report`는 `vote`에 의존할 수 없고 ArchUnit이 막는다). 신고도 같은 익명 쿠키를 쓰므로 `AnonCookieProvider`·`VoterResolver`가 하는 쿠키 처리를 `vote` 밖 중립 위치로 옮길지는 신고 이슈(M5, `로드맵.md`)에서 정한다. (#15에서 확정)
- `AnonId`의 public 생성자는 열어 둔다. "서명 검증을 통과한 값만 만든다"는 구조로 강제하지 않고 코드 관행으로 지킨다(DB 복원 경로에도 생성자가 필요하고, 쓰는 곳이 `AnonCookieProvider`와 `Vote` 둘뿐이다). 쓰는 곳이 늘면 다시 정한다. (#15에서 확정)
- 참여의 동시 요청에서 진 쪽은 선택이 같아도 409 `ALREADY_VOTED`이고 재조회하지 않는다. 유니크 제약 위반만 409로 바꾸고(`VoteWriter`), 외래키·CHECK 위반은 500이다. 이미 참여한 사람의 요청은 선택이 같아도 사전 조회에서 409다(재전송 200은 두지 않는다). 겹치는 구간이 같은 순간에 사전 조회를 통과한 요청뿐이고, 재조회를 위한 트랜잭션 분리가 과하다고 판단했다. 프론트는 `ALREADY_VOTED`를 받으면 상세 조회로 화면을 맞춘다. (#16에서 확정)
- 익명 쿠키의 Secure 속성은 `auddum.auth.cookie-secure`를 따르고, 오류로 끝난 요청에서는 새로 발급한 쿠키도 내리지 않는다. (#16에서 확정)
- 참여(vote) 서비스는 비즈니스 흐름만 보이게 한다. 서비스는 Repository를 직접 쓰지 않고 `VoteReader`(조회·집계), `VoteWriter`(저장·유니크 위반 번역), `VoterResolver`(참여자 결정, 회원이면 정상 상태 확인), `VoteValidator`(이미 참여했는지 확인), `VoteParticipator`(확인하고 참여시킨 뒤 결과 조립) 같은 `application`의 구현 클래스에 맡기고, 서비스는 시키기만 한다. 규칙은 도메인(`Vote.cast`, `Poll.isResultOpen`)이 판단하고 구현 클래스가 그것을 실행한다. 서비스가 받는 인자는 개념별로 묶은 record로 넘긴다: 어느 투표의 몇 번 선택지인지는 `PollChoice`, 요청한 사람의 신원 단서(회원 ID, 익명 쿠키)는 `VoterCredential`이다. 값 검증은 넣지 않고(형식은 투표 조회, 범위는 도메인이 한다), `VoterCredential`을 신고에서도 쓸지와 위치는 #60에서 정한다. 구현 클래스끼리의 참조는 허용한다. 한 클래스가 한 가지 일을 하게 하고, 필요해질 때만 클래스를 나눈다. 서비스가 `PollQueryService`를 부르는 부분은 알려진 예외이고 `PollReader` 도입과 규칙 전체는 #63에서 정한다. (#16에서 확정)
- 투표 목록(`GET /polls`)은 poll의 사용 사례이고 컨트롤러·DTO도 poll에 둔다. 참여 수는 poll이 필요한 것을 `ParticipantCounter`(poll.application) 포트로 선언하고, 참여 기록을 가진 vote가 `VoteReader`로 구현한다(`vote → poll` 방향 유지). 구현은 페이지의 투표 ID `IN` + `GROUP BY poll_id` 한 번이고, 카운터 컬럼·캐시는 두지 않는다(구현이 바뀌어도 포트는 그대로). 포트는 목록에 필요한 숫자 하나로 좁게 두고 필요가 생길 때만 늘린다. 계약은 "요청한 모든 투표 ID를 키로 가진 맵(참여가 없으면 0, 입력이 비면 빈 맵)"이고 0 채우기는 구현(vote)이 한다. 조회 최적화 인덱스는 M4 인덱스 항목에서 `EXPLAIN` 후 추가한다. 같은 기준(리소스의 주인이 사용 사례를 소유하고 다른 도메인의 데이터는 포트로 받는다)으로 투표 상세(`GET /polls/{id}`, 현재 vote)도 poll로 옮길지는 후속 이슈에서 정한다. (#62에서 확정)
- 위조 익명 쿠키 로그는 WARN이고 `[ANON_COOKIE_FORGED]` 태그와 `reason`(형식 오류, 서명 불일치)만 남기며 쿠키 원문은 남기지 않는다. 빈 문자열 쿠키는 쿠키 없음으로 본다. (#15에서 확정)

## 4. 알려진 한계 (고치지 않기로 한 것)

- 쓰기 서비스가 `getActiveMember`를 빠뜨리는 실수는 구조로 막지 않고 리뷰 항목으로 둔다.
- `reissue`의 10초 유예는 폐기 사유와 무관하게 적용한다.
- 만료된 리프레시 토큰 행 정리는 아직 없다.
- 정지된 관리자를 관리자로 볼지는 관리자 API(#52)에서 정한다.
- 참여자를 정하는 `VoterResolver.resolve(memberId, cookieValue)`(회원 상태 확인 포함)는 #16에서 컨트롤러가 `@CookieValue`로 받은 값을 서비스에 넘기는 방식으로 쓴다. 웹 계층 `ArgumentResolver`로 모을지는 신고 API가 같은 결정을 쓰게 될 때(M5, #60) 다시 정한다.
- 위조 익명 쿠키를 반복해서 보내면 WARN이 그만큼 늘어난다. 운영에서 빈도가 문제가 되면 그때 정한다.
