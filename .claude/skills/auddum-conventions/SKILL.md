# AuDDum 지원 규칙

test-writer와 domain-reviewer가 **같은 기준**을 쓰기 위한 공유 문서다. 기준이 에이전트마다 다르면 한쪽이 통과시킨 것을 다른 쪽이 차단한다.

## §2 테스트 규칙

| 종류 | 대상 | 도구 | 확인하는 것 |
|---|---|---|---|
| 도메인 단위 | `Poll`, `Member`, `Vote`, `Report` 등 | JUnit, 스프링 없이 순수 자바 | 마감 판단, 상태 전이, 선택지 소속, 값 객체 검증 |
| 서비스 통합 | Command·Query 서비스 | `@SpringBootTest` 또는 `@DataJpaTest`, H2 | 트랜잭션 경계, 유니크 제약, 재조회 |
| API | controller, 인증·인가, 오류 응답 | `MockMvcTester`, H2 | 상태 코드, ProblemDetail 형식, 쿠키 |
| 동시성 | 같은 신원의 동시 참여 | 실제 MySQL(컨테이너) | 기록 1건, 응답 201·200·409 |
| 구조 | 패키지 의존 | ArchUnit | 순환·다른 도메인 repository·`common` |

- 테스트 메서드(`@Test`) 이름만 한글 서술이다. 예: `마감된_투표에는_참여할_수_없다`. `@DisplayName`은 쓰지 않는다. 내부 헬퍼 메서드, 지역 변수, 상수, 픽스처 이름은 영어로 쓴다(`savePoll`, `closedPoll`, `QUESTION`).
- 클래스 이름은 `{대상}Test`다.
- 한 테스트는 규칙 하나만 확인한다. 정상 경로와 예외 경로를 따로 쓴다.
- 예외는 `isInstanceOf(AuddumException.class).hasMessage(...)`로 확인한다. 상태 위반은 오류 코드의 메시지(`PollErrorCode.POLL_CLOSED.getMessage()`), 입력 검증 실패는 필드별 사유 문구가 메시지다. `errorCode` 필드를 꺼내 비교하지 않는다.
- 테스트 지원 클래스는 레포에 있는 것을 상속한다. 없으면 만들지 말고 사용자에게 묻는다.
- 작성 형식은 `docs/개발-가이드.md` §3 "테스트 작성 방식"을 따른다: `WebApiTestSupport`를 상속하고 `mvcTester.get().uri(..).assertThat().hasStatus(HttpStatus.X).apply(print()).bodyJson().hasPathSatisfying(..)` 체이닝, `var`, `{도메인}Fixture`.
- Repository 쿼리 단독 테스트는 쓰지 않는다. 서비스 통합에서 간접 확인한다.

## §3 리뷰 기준 ID

domain-reviewer는 아래 표의 ID만 쓴다. 표에 없는 위반은 지적하지 않고 Objections에 남긴다.

**차단** (하나라도 있으면 FAIL)

| ID | 기준 | 근거 문서 |
|---|---|---|
| 정책-차단-1 | docs의 정책·규칙에 대응하는 구현이나 테스트가 없다 | 예외-정책 §4, 도메인-모델 규칙 |
| 정책-차단-2 | 경로·메서드·상태 코드·오류 코드가 API 명세와 다르다 | API-명세 |
| 정책-차단-3 | 도메인 규칙(마감·상태 전이·선택지 소속)이 서비스나 controller에 있다 | 도메인-모델, 아키텍처 §2 |
| 정책-차단-4 | 상태 전이·enum 값·용어가 도메인 모델과 다르다 | 도메인-모델 §1·§3~§7 |
| 정책-차단-5 | 명세에 없는 엔드포인트·필드·정책을 추가했다 | API-명세, 예외-정책 |
| 정책-차단-6 | 동작이 바뀌었는데 관련 docs가 그대로다 | 개발-가이드 §2 |

**권고** (PASS_WITH_FIXES)

| ID | 기준 |
|---|---|
| 권고-1 | 예외 경로 테스트가 정상 경로보다 부족하다 |
| 권고-2 | 테스트 이름·구성이 §2와 다르다 |
| 권고-3 | 코드 이름이 유비쿼터스 언어와 다르다(투표=Poll, 참여=Vote) |

**책임 결정**: 구현이 docs와 다르면 `구현자`, 테스트가 없거나 기대값이 docs와 다르면 `test-writer`, docs가 낡았거나 모호하면 `docs`(사용자 확인 필요).

## §4 커밋·브랜치

형식은 `docs/개발-가이드.md` §1~§2를 단일 기준으로 한다. 이 스킬에 복사하지 않는다 — 두 곳에 두면 어긋난다.
